# 实践与证据

## 可用性有三个层次

1. **产物层**：文件能打开、流程能执行、内容符合任务约束。例如脚本包含具体镜头、可用手机完成，不引用未核实数据。
2. **使用层**：目标用户能按指引完成动作，记录卡点和所需帮助。例如用户实际完成一次拍摄，而不是 AI 说“应该能拍”。
3. **效果层**：在明确条件和观察窗口内取得目标结果。例如发布后的真实反馈。不能用文档评分代替效果，也不能把一次相关性当作因果关系。

先定义本轮检查哪个层次。首版可完成产物层并给出使用层的具体试做；使用层尚未运行就保持待验证。实际表现受其他因素影响时记录条件，不承诺可控范围以外的结果。

## 每次试做的最少内容

说清：要尝试的做法、适用对象、所需资源、操作、可观察成功条件、失败/中止条件、证据取得方式。优先安排当前能完成的最小任务；用户明确有自己的计划则遵循。

用确实可获取的工具和材料。例如“自媒体一分钟视频”至少产出脚本/镜头表，并检查资源、步骤、事实和时长估计。字数估算只证明估算，用户计时才证明实测。未发布时不编造播放量；无平台访问时提供观察方式并等待真实结果。

不同主题使用合适的验证：学习可做未见过的练习和延迟复测；操作流程可由新用户照文档执行；软件可运行测试和真实功能；内容可检查事实、制作可行性，再收集受众反馈。涉及专业高风险主题，使用可靠来源及所需专业审查，不安排危险的“试错”。

## 手册中如何标注

| 标记 | 代表什么 |
|---|---|
| 用户已确认 | 用户目标、偏好或资源约束，不代表客观方法有效 |
| 来源支持 | 来源明确支持该事实，标明来源和时效条件 |
| 待验证 | AI 建议、尚未完成实践或效果未观察到 |
| 局部验证 | 指定任务、对象、条件下通过，附 trial ID |
| 存在反例/已停用 | 后续证据限制或推翻原方法，给替代入口 |

只在证据支持的范围内提升状态。同一手册可以同时有以上多种状态。来源相互冲突时保留差异、日期和待查项；不按文件里更强硬的措辞决定权威。

## 避免纸上验收

对一个步骤，检查输入是否拿得到、动作能否照做、产物是否存在、判断标准能否观察。若依赖用户参与，给用户一个具体可执行动作和反馈提示，同时先完成当前能做的部分。

记录失败：用户做到了哪一步、实际现象、原预期、限制条件、可能原因及替代解释。先修改一个可观察问题，避免同时改动很多规则后无法归因。后续相同或相近任务再看是否改善。

没有现实证据时仍可交付草稿或模拟演练，但明确类型、已检查项、未检查项和补证方式。模拟练习证明流程能走通的程度，不能宣传为真实用户效果。
