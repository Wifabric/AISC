# AISC Workbench v2.1.19-preview.1

本版集中处理 11 月 13 日及 18 日的 15 条反馈，改善技能批量操作、文件整理、标签与工作记录对应关系，以及代理节点管理。随 Workbench 提供 AISC CLI **0.3.0.dev0**，保持 serve protocol 4。

**当前为开发候选，PR #104 已合入 develop，收尾修复见 PR #105；尚未发布 GitHub Release，也未收到 leader 功能验收结论。** 本地及远程桌面实测已覆盖下列主要操作；安装自动化与人工向导的验证状态分别记录，见文末及交付记录。

## 技能安装与更新

- 修复技能位于仓库嵌套子目录时，整组“安装全部”和“更新全部”找不到 `SKILL.md` 的问题。除既有目录外，可按技能相对路径定位唯一匹配的目录。
- 安装和更新继续使用原技能的登记与启用状态；缺失或无法唯一定位的技能保留失败结果，不把未安装的内容报成成功。拒绝越出仓库或技能目录的异常链接。
- 在隔离工作区通过真实 `mattpocock/skills` 仓库验证：20 项批量安装、20 项批量更新完成，刷新后可查看安装结果。该数量是本轮测试时的仓库状态。

## Provider 与官方直连

- 新建 Codex Provider 时，API 格式默认选择 **OpenAI Responses**；编辑已有配置仍沿用其保存的格式，不批量改写用户配置。
- Codex 新建模板列表隐藏火山引擎 Ark；新建时按选中的 API 格式填入对应端点。原生格式下 DeepSeek、智谱、Kimi 分别使用 `https://api.deepseek.com`、`https://open.bigmodel.cn/api/v1`、`https://api.moonshot.cn/v1`。用户手动修改的地址保留。
- 刷新当前 Claude/Codex 官方直连卡时，重新应用当前官方配置，减少卡片状态与实际会话配置不一致的情况。
- 用户已报告账号手动测试通过。此结论限于其实际测试的配置；原反馈中重建卷后的权限错误尚未复现，未宣称所有权限问题已经解决。

## 文件管理与远程工作区

- 文件树新增“移动”操作：可通过右键选择目标目录，也可将单个文件或目录拖到工作区内的目录。本地工作区与 SSH 工作区均接入实际文件操作。
- 同名目标不覆盖；拒绝移入自身子目录及不符合路径约束的目标。失败时保留源文件并显示错误，文件系统不支持安全移动时不会退回到可能覆盖目标的操作。
- 修复 Windows WebView 中单项拖动不生效的问题。拖入终端时只插入转义后的路径，不自动执行；本轮已验证真实 SSH 工作区的目录拖动、冲突保护及拖入 Bash。
- 远程最近工作区列表调整机器名、路径与操作区布局，长路径省略显示，避免把机器名挤成多行。

## 标签、分屏与终端

- 终端标签可左右拖动排序，排序不会切换正在操作的会话；修复桌面端原生拖动未生效的问题。
- 新建标签及新分屏前可选择工作区内的启动子目录。例如左侧在 `frontend`、右侧在 `backend` 启动，各分屏独立使用自己的目录。
- 标签与工作记录采用对应编号，并以颜色区分 Claude、Codex 和 Bash；双击已关联记录的标签可定位到对应工作记录。独立终端保留自己的编号。
- 加宽终端滚动条，便于拖动查看历史输出。Codex 新建与恢复会话使用上游内联模式，修复默认全屏模式下外侧滚动条无法拖动的问题；不修改全局 Codex 配置。已实测 Bash 300 行、Claude 本地模拟接口生成的 220 行输出，以及 Codex 原生四轮历史的回看与返回末尾。
- 标签排序用于当前打开的工作区。重新打开工作区仍按既有设计从单个 Bash 标签开始，不表示恢复全部旧标签及进程。

## 会话与工作记录

- 按引擎与原生会话 ID 整理记录。Codex 存在可用的原生会话索引时，优先读取原生恢复操作指向的文件；没有可用索引时才按文件最近写入时间选择。复制旧日志产生的新文件时间不再覆盖原生记录选择；索引损坏时仍可读取导入记录。
- 按原生日志提供的父子关系显示层级；新发现的后代可归入父记录所属集合。缺少父级信息的记录保留在未归档区，不猜测归属。
- 移动父记录时一并处理后代；删除确认显示实际影响的记录数量。通过父、子、孙及无关记录的受控样本验证：整体移入、移出及删除三条，保留无关记录。
- 反馈者原始日志的显示与继续会话一致性仍需原样本核对，受控样本通过不代表该自然场景已经复现。

## 网络、镜像与 Docker

- 设置页可打开当前工作区的“网络与用量”。运行新版镜像并导入订阅后，可查看可手动选择的代理组、切换节点并测延时；刷新后读回当前选中的节点。
- 导入订阅后同步刷新启动摘要，避免面板已成功导入，启动页仍显示旧的“未导入”提示。
- 新构建的工作站镜像默认安装 GitHub CLI `gh`。涉及技能、Provider 适配器、代理节点和 `gh` 的功能需要新版镜像；只替换桌面程序不会更新旧容器内的文件。
- 构建进度按提示内容去重，减少相同警告重复显示。
- 修复 Docker 端口占用后的启动重试：先清理本次失败创建的容器再换端口，避免残留对象导致下一次误报名称冲突；不强制删除正在运行的容器。
- 设置 → 磁盘与缓存 →“重置 Docker Desktop…”打开 Docker 官方 Dashboard，并提示进入右上角 Troubleshoot → Reset to factory defaults。最终影响范围与确认由 Docker 展示，AISC 不自动清空容器、镜像或数据卷；打不开 Docker 时显示错误并保留操作指引。官方确认流程已获用户确认，桌面入口已实际验证。

## 试用与兼容性

- 推荐将本版 Workbench、CLI **0.3.0.dev0** 和同一候选的完整 `aisc-bundle` 配对使用。远程 SSH 机器也需部署对应 CLI，旧 CLI 即使同为 protocol 4，也可能缺少新增的文件移动等操作。
- leader 可先按[功能验收教程](../plans/2.1.19-dev-plans/HANDTEST.md)测试源码构建或完整便携候选；新功能验收和安装包验收分别记录。
- 本地已生成 `AISC-Workbench-2.1.19-preview.1-setup.exe` 及 `.sha256`；产物位置、校验值和测试证据见[交付记录](../plans/2.1.19-dev-plans/DELIVERY.md)。尚无本版公开下载地址，不通过旧版自动更新入口承诺取得本候选。
- CLI 独立 pip 包不包含镜像构建资源；本轮未发布 CLI 0.3.0.dev0 到 PyPI/TestPyPI，也未创建独立 CLI 下载资产。

## 验证结果与已知限制

- 收尾本地回归：前端 **902 项通过（107 个文件）**；Python **1841 项及 220 项子测试通过、74 项跳过**；Rust 回归通过。环境门控的 SSH/运行时用例不能用 Rust 的成功汇总代替真实执行证据。
- 修复 Windows 非 UTF-8 系统编码下的 Provider 模型目录日志问题：诊断日志固定 UTF-8，日志写入错误不再打断模型发现；原失败用例与新增编码回归通过。两个引擎的受控权限拒绝和恢复检查通过，未把受控错误等同于反馈者原始故障已复现。
- 本机沙盒曾拦截旧版和候选未签名安装器，临时环境已按用户截止要求清理。后续安装验证改用一次性 GitHub Windows runner；正式 2.1.18 升级、真实样本保留、CLI/PATH、原生窗口启动及静默卸载分别留证。最新结果见[交付记录](../plans/2.1.19-dev-plans/DELIVERY.md)，自动化不代替图形向导、依赖安装和交互卸载验收，也不解决未签名包在强制应用控制环境中的准入。
- 单标签偶发卡死未复现，按用户要求跳过；已有终端重绘改动和有限输出检查，不作为原问题已解决的依据。
- PR #104 已合入，收尾 PR #105 的 CI 和桌面补验持续回写交付记录。正式发布、反馈 resolved 状态和计划归档等待对应发布条件；leader 结论单列，不由开发者代签。
