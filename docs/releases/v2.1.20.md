# AISC Workbench v2.1.20

本版处理 11 月 19 日和 23 日收到的 11 条反馈。重点是从 **2.1.19 覆盖升级后保留原工作区的 Provider**，以及让技能市场、终端和工作记录在实际使用中更可靠。随 Windows x64 安装器提供 AISC CLI **0.3.1**。

本版由已通过用户验收的 **2.1.20-preview.3** 定版。复测还覆盖了市场搜索 `matt` 只显示 20 条、容器内升级 Codex 后启动报错，以及快速滚动或来回切换终端标签时卡住的问题。

## Provider 与覆盖升级

- 从 2.1.19 升级时，保留已填写配置、正在使用或已加入故障转移队列的旧预置。打开侧栏「供应商」，分别切到 Claude 和 Codex，每个引擎各有一张「官方直连」卡。等价的旧入口会合并，自建 Provider 仍保留名称和编辑入口。
- **升级后如果只看见「官方直连」**，先核对打开的是原项目的完整路径，并沿用升级前的 AISC 数据目录。不同工作区各自保存 Provider，即使窗口标题都叫 `workspace`，读到的也可能是两份配置。回到原工作区后再点「刷新」核对，无须先重新录入 API Key。
- 实机从正式 2.1.19 覆盖到 Preview 后，原工作区的 **4 张第三方 Provider 卡片**均保留。另在一次性 Windows 环境用 2.1.20 候选安装器复测，升级前后工作区 Provider 数据库逐字节一致。

## 代理节点与用量

- 进入「设置 → 网络与用量」，在「代理节点」点击「刷新代理节点」。手动策略组会显示候选节点和当前节点；选另一项后点「使用节点」，再刷新即可核对切换结果。「故障转移」「自动选择」等自动组会说明由策略选取节点，也可在该行测延时。
- 如果刚更换订阅，按提示以代理模式重开工作区，使容器加载新配置。旧镜像缺少节点组件、订阅尚未应用、控制接口尚未就绪时，页面分别提示下一步操作。
- 同一页的「用量统计」分别列出 **Provider 用量**和**按模型用量**。可按时间、工作区筛选，再点「刷新用量统计」。缩窄或缩短窗口后，可滚动到节点和用量各自的操作按钮。

## 技能市场：搜索、加载更多与单项安装

- 在「扩展 → 扩展市场 → 技能」搜索 `matt`，结果列表上方分别标出**已显示条数**和**本次搜索返回条数**。首批显示 20 条。如果还有结果，点计数旁的「加载更多」继续展开。整组安装按钮标出本组当前已显示、将要安装的数量。
- 本轮实测搜到 **200 条去重结果**，其中 **53 条来自 `mattpocock/skills`**。这是当次返回值，后续数量随上游目录变化。
- 单选 `garrytan/gstack` 下的 `office-hours` 时，安装所选技能及它实际调用的共享文件和辅助程序，已有技能保留。用本版配套资源重建 x64 镜像后，首次安装可使用镜像内置的源码和 Bun。市场搜索、显式更新仍需联网。
- 安装后重新打开已启用该技能的 Claude 或 Codex 会话，再调用 `office-hours`。本轮在全新配置目录做过断网首装，并验证了两个引擎的入口和上游辅助程序。

## 终端复制、滚动与 Codex 启动

- 启用「选中即复制」后，在 Claude 或 Codex 中向上滚动多屏，再连续框选不同文本，每次复制的都是当次选区。原有右键复制和普通 Bash 的操作方式保留。
- 修复密集滚动滚轮或快速来回切换顶部标签时出现的卡住问题。本轮用长输出连续执行这两种操作，再检查终端输入和标签切换，用户已完成复测。
- 修复容器内升级 Codex 后，新标签启动时可能停在 `failed to clean up stale arg0 temp dirs: Permission denied` 的问题。对已有工作区，使用本版资源重建镜像、重开工作区，再新建 Codex 标签即可使用已升级的版本。

## 工作记录：预览、导出与删除

- **预览执行详情。** 右键 Claude 或 Codex 的记录，选择「预览」。「思考与执行」默认收起，展开后可读技能内容、工具参数和返回结果。例如 `exec` 读文件时，可核对执行的命令、工作目录及输出。正文中的有效工作区文件和网址可点击，缺失文件保留可读的文件名。
- **导出完整对话。** 右键记录导出，或从预览右下角点「导出 Markdown」，均可选择文件名和保存目录。即使屏幕只预览了部分长记录，导出文件也会保留后面的对话和中文结尾。取消保存会保留已有文件。
- **看清删除范围。** 右键单条记录或整个集合会弹出确认框，说明受影响的记录和运行中的成员会话。拖入集合的记录保留原标题，确认删除集合后，相应成员会话会结束，其他打开的标签仍可使用。按 Esc 可取消操作。

## 新标签与集合中的会话

- 在顶部标签栏的新建菜单输入工作目录前缀，候选只显示匹配的目录，并可继续选下一级。带空格的路径也可选，例如在 `demo project/backend/` 启动 Bash 后，运行 `pwd` 即可核对实际位置。
- 在「工作记录」里点**目标集合自己的加号**，同样可以选目录并启动 Claude、Codex 或 Bash。从这里直接启动的引擎会话，以及从「个人能力与主题」发起的首个引擎会话，都会归入该集合。Bash 在所选目录打开。

## 安装、升级与文件校验

1. 从正式发布页的 **Assets** 下载 `AISC-Workbench-2.1.20-setup.exe` 和同名 `.exe.sha256`。在下载目录运行下面的命令，将结果与校验文件对照。此版 Windows 安装器未签名，有强制签名要求的设备仍可能阻止运行。
2. 首次使用请安装并启动 Docker Desktop。从旧版升级时，先保存工作、关闭工作区，再运行安装器覆盖安装。升级完成后打开**原工作区**，核对 Workbench **2.1.20** 和随包 CLI **0.3.1**。
3. 代理节点控制、容器内 Codex 启动和 `office-hours` 离线首装涉及镜像内的资源。使用安装器随附的新版 `aisc-bundle` 重建工作区镜像，再打开工作区。使用 SSH 工作区时，远端也需部署配套 CLI 和资源。

```powershell
Get-FileHash '.\AISC-Workbench-2.1.20-setup.exe' -Algorithm SHA256
```
