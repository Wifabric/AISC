# AISC v0.3.0

随 AISC Workbench **2.1.19** 提供的正式 CLI。新增运行中工作区的代理节点控制、会话启动子目录及远程文件移动，修正工作记录归属和运行时端口冲突重试。保持 serve protocol **4** 与现有 JSON envelope 契约。

**版本已定为 0.3.0，功能与已验收的 0.3.0.dev0 一致。** Workbench 安装器提供随包 CLI；独立 pip 渠道通过 `cli-v0.3.0` 对应的 TestPyPI/PyPI 流水线发布和验证，实际渠道状态见交付记录。

## 代理节点控制

- 新增 `aisc network nodes list/select/delay`，通过运行中工作区的 Mihomo 控制接口列出手动选择组、切换节点或测延时。
- 必须指定 `--workspace` 与 `--runtime-id`；切换和测速还需提供列表中实际存在的 `--group`、`--node`。工作区需要运行本版资源构建的代理镜像并配置订阅。
- 目标停止、旧镜像缺少适配器或节点请求失败时返回明确错误，不把失败包装成成功。控制接口使用容器内 Unix socket，不新增宿主公网监听端口。

```bash
# 替换为正在运行的工作区和实际 runtime ID；组名与节点名取自 list 输出
aisc network nodes list --workspace /path/to/project --runtime-id <runtime-id> --format json
aisc network nodes select --workspace /path/to/project --runtime-id <runtime-id> --group "组名" --node "节点名"
aisc network nodes delay --workspace /path/to/project --runtime-id <runtime-id> --group "组名" --node "节点名"
```

`list` 返回各组的可选节点及当前节点；`select` 返回本次选择；`delay` 返回测速结果。订阅导入和刷新仍使用既有 `aisc network subscription` 命令。

## 会话启动与工作记录

- `aisc session open` 新增 `--working-directory`，接受相对于工作区的子目录，供 Workbench 新标签与分屏使用。原有 `--runtime-id`、`--session-id`、`--agent` 仍为必需参数；不传子目录时沿用原入口。
- 按引擎和原生会话 ID 归并日志；Codex 优先采用原生 SQLite 索引指定的会话文件，没有可用索引时才按最近写入时间选择，保留原生恢复身份。
- 利用原生日志的父子信息归档新后代；父级信息缺失时保留未归档状态。移动或删除父记录时处理后代，减少残留孤立记录。
- 父、子、孙的受控样本通过移动与删除验收；Codex、Claude 的预览与继续会话内容一致性通过本轮验收。

## 文件服务与容器适配器

- serve 文件操作新增 `fs.move`，供 SSH 文件树移动文件和目录；目标存在、自身子目录及不符合链接/路径约束的请求被拒绝，不覆盖原目标。
- 嵌套目录技能按相对路径定位唯一的 `SKILL.md`，修复整组安装和更新找不到技能源的问题；缺失或异常链接继续报错。
- 官方直连卡刷新时重新应用当前配置；智谱 Codex 原生端点补为 `https://open.bigmodel.cn/api/v1`。新建 Codex 默认 Responses 和模板可见性由配套 Workbench 界面处理。
- 本版镜像新增 GitHub CLI `gh` 和代理节点适配器。镜像内脚本改变后，需要用对应 bundle 重新构建镜像，旧容器不会随 CLI 替换自动获得这些文件。

## 运行时修复

- 新建和恢复 Codex 会话使用 `--no-alt-screen`，使 Workbench 滚动条可以回看原生历史；不修改用户全局 Codex 配置。新版容器脚本需要重建镜像后生效。

- Docker 端口绑定冲突后，在切换下一个端口前清理本次失败创建的容器，避免重试被残留名称阻挡。
- 清理对象限定为本次创建命令返回的完整容器 ID；不强制删除正在运行的容器，清理失败时保留原错误。
- 定向回归覆盖端口冲突和清理边界；真实 SSH 工作区验证过占用 47000 后改用 47001 启动。

## 配对、验证与发布边界

- 推荐与 Workbench **2.1.19** 及同候选 bundle 配对。远程机器需使用对应源码/构建的 CLI；protocol 4 一致不代表旧 CLI 已实现新增操作。
- CLI 源码版本由 `src/aisc/VERSION` 读取；正式目标 0.3.0、tag 为 `cli-v0.3.0`，走独立 PyPI 发布流程。源码版本、CLI JSON fixture 与本发布说明保持一致，构建前执行版本契约检查。
- 独立 pip 包不包含镜像构建资源，Workbench 安装包提供配套 bundle；独立 CLI 用户仍需按开发手册准备相同版本的资源根，以实际可用的 bundle 资产为准。
- 收尾 Python 全集 1841 项及 220 项子测试通过，74 项按环境条件跳过。Windows 非 UTF-8 模型目录诊断日志的失败已修复，并验证日志写入异常不影响模型发现；用户已有账号验收不重复执行。
- Codex 工作记录读取优先采用原生 SQLite 索引指定的会话文件，避免复制旧日志后预览与原生恢复选择不同副本；索引不可读时保留导入记录的读取能力。
- Windows 安装后 CLI/PATH、升级后的原生记录读取及随包资源定位在一次性 Windows runner 检查；2026-11-19 用户确认剩余安装交互手测全部通过，分项来源见交付记录。本轮回归与用户验收绑定 0.3.0.dev0；正式 0.3.0 已随 Workbench 2.1.19 重新构建并通过安装升级检查；独立渠道状态见下文。

完整功能见 [Workbench 发布说明](v2.1.19.md)，验证日志和遗留项见[交付记录](../archive/2.1.19-dev-plans/DELIVERY.md)。
