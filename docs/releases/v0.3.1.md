# AISC v0.3.1（CLI）

本版随 **AISC Workbench 2.1.20** 提供，保持 **serve protocol 4**。相比 0.3.0，CLI 可将原生会话完整导出为 Markdown，能说明代理节点刷新失败的原因，并修复了工作区 Provider 迁移和容器内升级 Codex 后的启动问题。

## 会话读取、导出与集合归属

`aisc conversation read` 新增 `--markdown`。从 `aisc conversation list` 找到目标会话的原生 ID，传入对应引擎和同一个工作区，即可导出完整可读对话。下面以 Bash 中导出 Codex 会话为例，先将路径和会话 ID 换成自己的值。

```bash
aisc conversation list --workspace "/path/to/project" --format json
aisc conversation read --workspace "/path/to/project" --agent codex \
  --conversation-id "替换为会话原生ID" --markdown --format text > conversation.md
```

- 文件包含预览窗口截断位置之后的内容。客户端分段导出长记录时，可用 `--markdown-cursor start --format json` 取第一页，再将返回的 `next` 作为下一页游标，直到 `next` 为 `null`。
- `aisc work-record list` 在同一次查询中返回集合、未归档会话和会话详情。Workbench 据此保留拖入集合的原始标题，删除集合时匹配并终止对应的活动成员会话。

## 代理节点与故障定位

在已启动并应用订阅的代理工作区执行节点查询。把 `--runtime-id` 换成该工作区正在运行的实例 ID。

```bash
aisc network nodes list --workspace "/path/to/project" --runtime-id "替换为运行实例ID" --format json
```

- 每个策略组返回 `current`（当前节点）、`nodes`（候选节点）和 `selectable`（是否可手选）。`selectable` 为 `true` 的组可使用 `nodes select` 切换，再用 `list` 读回；自动组仍可用 `nodes delay` 测延时。
- 遇到 `AISC_ERR_PROXY_IMAGE`，用本版资源重建镜像。遇到 `AISC_ERR_PROXY_CONFIG`，以代理模式重开工作区，使订阅生效。遇到 `AISC_ERR_PROXY_SOCKET`，等待代理启动后重试；若持续出现，再查看代理日志。

## Provider 迁移、技能安装与运行时

- 升级迁移保留已配置、正在使用或已进入故障转移队列的旧 Provider 预置。配置与所选工作区及 AISC 数据目录关联，排查升级后列表为空时应先核对这两个位置。
- 市场适配器可取得超过 20 条的搜索结果，供 Workbench 分批展示。单项安装 `office-hours` 会准备该技能依赖的共享文档、辅助程序和 Bun。已用本版 x64 镜像验证全新配置目录下的断网首装；搜索及显式更新仍访问上游。
- 工作区重建容器时，为 Codex 提供可写的临时目录，解决升级后清理 `arg0` 目录出现的权限错误。使用新版资源重建镜像并重新打开工作区，已有 Codex 配置、会话和持久工具链继续沿用。

## 安装、配对与验证

Workbench 安装器已包含 CLI **0.3.1** 和配套 `aisc-bundle`。独立 Python 分发名为 `aisc-cli`，命令名为 `aisc`。正式 PyPI 上线后，可用以下命令安装并核对版本。

```bash
pipx install aisc-cli==0.3.1
aisc version --format json
```

- 输出中的 `data.cli_version` 应为 `0.3.1`。纯 pip 环境的 `data.bundle_version` 可能为 `null`；需要构建镜像时，请准备配套的完整资源目录，并用 `aisc --aisc-root "/path/to/aisc-bundle" version --format json` 核对两个版本。通过 SSH 使用新增操作时，远端也应使用 CLI 0.3.1。
- wheel 和源码包均通过严格元数据检查、干净环境安装、重装及卸载后重装，另已通过 pipx 和脱离源码目录的安装检查。Windows 候选安装器里的 CLI 已实际读取覆盖升级前的原生会话，并导出了超出预览长度的 Markdown。
- 独立发行使用标签 `cli-v0.3.1`，先在 TestPyPI 验证安装，再经审核发布至正式 PyPI。桌面安装器随 Workbench 标签 `v2.1.20` 分发。[Workbench 变更与升级说明](https://github.com/Wifabric/AISC/blob/v2.1.20/docs/releases/v2.1.20.md) · [整版验证与渠道记录](https://github.com/Wifabric/AISC/blob/v2.1.20/docs/plans/2.1.20-dev-plans/DELIVERY.md)
