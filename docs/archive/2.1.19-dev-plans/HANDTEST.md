## 2. 准备一个可丢弃的工作区

1. 确认 Docker 可用，启动候选后核对 Workbench 版本及实际使用的 CLI。若来源不明，先记录版本和路径再继续。
2. 在 D 盘或测试机约定目录创建 `aisc-release19-qa`，其中准备 `A`、`B`、`dest` 三个目录。
3. 在 `A` 放入 `file.txt`（内容“源文件”）、`conflict.txt`（内容“源冲突文件”）及 `folder/child.txt`；在 `dest` 放入同名 `conflict.txt`（内容“目标保留文件”）。
4. 使用本候选的资源构建并选择专用测试镜像。旧镜像不会因替换桌面程序自动获得技能修复、代理节点适配器和 gh。
5. 启动该测试工作区。应用数据目录的隔离不代表工作区文件或宿主 Docker 引擎也被隔离；后续只操作这个测试目录和专用资源。
6. 验证远程文件操作时，在已有 SSH 测试机准备同样目录，并部署对应 CLI 0.3.0。没有远程环境就记录 NOT RUN，不能用本地结果替代。

不要为本轮验收重置日常 Docker Desktop，也不需要重复测试用户已确认的 Provider 或已要求跳过的偶发卡死。

## 3. 逐项验收新功能

### T1：整组技能安装与更新

1. 打开“扩展 → 技能市场”，检索 `mattpocock/skills`，记下当前分组显示的总数。
2. 点击“安装全部”，等待操作结束，刷新已安装列表，核对成功数量和失败提示。
3. 对同一组点击“更新全部”，等待结束后再刷新。
4. 如需检查启停保留，先记录一个技能的启用状态，更新后再次对照。

**预期**：嵌套目录技能能定位并安装；更新完成后技能仍在，已有启停状态保留。失败项应能辨认，不能把失败数忽略。本轮开发者实测时该组为 20 项；上游数量改变时以当天列表为准。

### T2：本地文件和目录移动

1. 将 `A/file.txt` 通过右键“移动”移到 `dest`，打开确认内容，检查原位置已没有该文件。
2. 将 `A/folder` 拖到 `dest`，确认 `folder/child.txt` 随目录移动且内容保留。
3. 尝试将 `A/conflict.txt` 移到 `dest`。

**预期**：前两次成功；第三次提示冲突，源和原目标均保留，内容没有被覆盖。拖动移动的本轮重点是单项文件或目录，不把它当作新增的批量移动承诺。

### T3：SSH 文件操作与拖入终端

1. 在远程测试工作区重复 T2，分别核对远程源和目标内容。
2. 将一个远程文件拖入空闲 Bash 输入行。
3. 查看最近工作区列表中的机器名和长路径。

**预期**：远程移动与冲突保护成立；终端出现带适当转义的路径且不自动执行；机器名不会被长路径挤成多行。文件系统不支持安全移动而明确拒绝时，应记录环境和错误，不能改用覆盖目标的操作制造成功结果。

### T4：新标签与分屏的启动目录

1. 从标签栏新建入口选择目录 `A`，再创建 Bash；执行 `pwd`。
2. 新建分屏时选择目录 `B`，创建 Bash，再执行 `pwd`。
3. 返回第一个分屏再执行 `pwd`，并尝试切换分屏方向及关闭其中一个分屏。

**预期**：各分屏分别进入工作区内的 A、B；创建第二个分屏不会改变第一个的目录；关闭一个不误关另一个。

### T5：标签排序、编号与工作记录定位

1. 打开至少三个标签，记住当前正在操作的标签。
2. 将最左标签拖到右侧，再反向拖回。
3. 打开一个已关联工作记录的会话，双击其标签。

**预期**：顺序按拖动改变，当前会话不被误切换；关联标签能定位对应记录，引擎颜色与编号可区分。重新打开工作区仍从单个 Bash 开始，这是现有行为，不把它误报成未恢复旧进程。

### T6：工作记录的父子关系、移动与删除

1. 准备可丢弃、原生日志包含父子关系的记录，以及一条无关记录；优先用真实会话。只有普通独立记录时，不能声称测过父子关系。
2. 将父记录移入一个集合，检查子记录及孙记录是否一起移动；再移出并核对。
3. 删除父记录，先核对提示中的影响数量，点击取消，确认所有记录仍在。
4. 对同一批可丢弃样本再次删除并确认，检查后代被一并删除、无关记录保留。

**预期**：层级、影响数量和实际结果一致。开发者父/子/孙受控样本，以及 Codex、Claude 预览与继续会话内容一致性已通过。

### T7：订阅、节点切换与测速

1. 在运行中的测试工作区，从设置打开“网络与用量”，导入有权使用的测试订阅。
2. 关闭面板，确认启动摘要不再保留旧的“未导入”提示。
3. 刷新订阅并列出节点，在手动选择组中切换到另一个节点。
4. 再次刷新，检查当前节点；对选中节点测速。
5. 切换选项，确认不会继续显示上一个节点的旧测速结果。

**预期**：列表、选择和刷新读回一致；测速返回延时或明确错误。失败时区分订阅、网络、容器状态和应用报错，截图中隐藏订阅地址。

### T8：镜像、gh 与重复提示

1. 使用本版 bundle 构建测试镜像，观察进度中的相同提示是否反复出现。
2. 在该镜像的 Bash 中执行 `gh --version`。
3. 打开设置 → 磁盘与缓存 →“重置 Docker Desktop…”，确认打开官方 Dashboard；查看 Troubleshoot 入口后退出，不执行恢复出厂。

**预期**：构建状态可追踪、相同提示不重复堆积；gh 能给出版本；重置入口明确说明后续操作与影响。本项不要求真的重置 Docker Desktop。

### T9：滚动条与终端回滚

在测试 Bash 执行 `seq 1 300`，拖动右侧滚动条回看前面的行，再回到底部。

**预期**：可查看历史行并返回末尾。开发者已实测 Bash、Claude 220 行受控输出、Codex 四轮原生历史的拖动与返回；leader 如复测，分别记录引擎和样本。用户已要求跳过的偶发卡死不纳入本次继续测试。

### T10：Provider（用户已手测，默认不重复）

保留参考步骤：新建 Codex Provider 检查 Responses 默认值、Ark 模板隐藏和端点；编辑旧配置核对格式/地址保留；刷新当前官方直连卡后用本人账号验证对话。

**已有结论**：用户报告账号教程全部通过。空目录模型发现的 Windows 编码单测已修复并复测通过。两个引擎受控权限拒绝和恢复均通过，本项已收口。
