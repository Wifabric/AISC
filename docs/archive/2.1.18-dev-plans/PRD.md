# 2.1.18 产品规格

状态：R-1–R-10、D-17 三层能力与 S16 均已实现、集成并获用户验收；U-1–U-4 已裁定。Workbench 已正式发布，PyPI 审批/反馈回写按用户要求暂缓，见 [发布准备](release-readiness.md)。

## 目标与验收

| 需求 | 用户完成的事情 | 可观察验收标准 | 批次/手测 |
| --- | --- | --- | --- |
| R-1 | 把文件或目录 `Area` 改为 `AREA` | 磁盘实际条目名精确为 `AREA`，内容/子文件不丢；列表刷新仍一致；其他同名目标不被覆盖 | b1 / H1 |
| R-2 | 在窗口底部使用工作记录右键菜单 | 菜单与子菜单可见且可操作，必要时向上/向左；小视口可滚动，Escape 关闭并恢复焦点 | b2 / H2 |
| R-3 | 自己命名镜像 | 可编辑完整镜像引用；非法/冲突输入有明确错误；操作对象仍是选择的镜像，旧 tag 语义依 U-1 | b3 / H3 |
| R-4 | 从镜像行或启动摘要重建 | 显示目标、镜像/容器预检查、缓存选项及流式进度；默认无缓存；运行容器存在时不悄悄停删；失败保留旧可用镜像 | b4 / H4 |
| R-5 | 查看并编辑一组科研/开发扩展 | 单项推荐仍可使用；模块包含有明确来源的 Skill/MCP/Plugin；可创建/编辑/删除定义，修改后重启可恢复，编辑本身不执行安装 | b5 / H5 |
| R-6 | 一次应用或卸载模块 | 每项有成功/失败/保留/待认证等可区分结果；失败可重试；共享/预装项按确认规则保留；新工作区不会显示另一目标的已安装状态 | b6 / H6 |
| R-7 | 安装插件并确认真实结果 | 指定插件安装后列表与磁盘一致；超时后能核对终态，重复点击/重试不重复安装，诊断可用 | b7 / H7 |
| R-8 | 在 GitHub MCP 项完成首次配置 | 入口清晰，用户本人提供授权；Claude/Codex 状态分别真实刷新；取消不改旧配置，错误/日志不泄露凭据 | b8 / H8 |
| R-9 | 搜索 grill 并查看子技能介绍 | 搜索与详情分开呈现状态，grill-me 可读取有效简介；404/超时/断网可诊断与重试，来源可访问 | b9 / H9 |
| R-10 | 关闭当前错误提示 | 只关闭当前展示，保留诊断历史/操作状态；新失败重新显示，工作区间状态隔离，键盘可用 | b10 / H10 |

## 范围

- 需求 R-1–R-10 纳入规划（F5–F8 对应 R-7–R-10，D-11）。UI 文案及新字段须中英一致；目标机器、工作区和运行实例身份贯穿异步操作。
- R-3、R-4、R-5、R-6 的产品语义依 U-1–U-4；U-1/U-2/U-3 按 D-13，U-4 按 D-17 的已确认方案执行。

## 非目标

- 不重写实时终端渲染，不另造扩展下载器、模型配置管理器或替代 cc-switch 的安装事实库。
- 不做无关运行工具全量升级；不因为旧本地构建带 `.dev0` 就降级正式版本。
- 不把模块删除等同于用户资产清空，不自动覆盖或发布用户已有资料。
- 按 D-12/D-15 分批测试集成、统一 Preview；三层能力与 S16 进入本版，仍分别记录各反馈的验证证据。

## 完成定义

每个需求都必须有：对应批次实现提交、相关自动化、必要真实数据面、Windows CU（或 NOT RUN 理由）、用户验收裁定。UI 展示“成功”必须有后端终态支撑；未知状态不能作为成功。

版本级收尾由用户触发；全部完成或显式转期后再走 preview/final 工作流。反馈站只在符合开发指南的实际发布节点更新，本版计划创建不会改变反馈解决状态。
