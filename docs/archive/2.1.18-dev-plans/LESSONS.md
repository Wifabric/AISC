# 本阶段经验与约束

## 2026-11-09 交付遗漏复盘

- 根因：把功能验收和 main 合并当作停止点，未逐项核对正式分发、用户教程、开发日志、反馈与归档；只在文首加覆盖说明，也留下了多处互相冲突的“当前状态”。
- 修正：按批准需求、现行规则、仓库差异和用户实际入口双向检查；当前账本更新真实状态，历史验证加日期/性质，不把未测改成通过。
- 完成门：Release 可下载、CLI 索引可安装、文档与版本相符、八条反馈有实际结果、归档可追溯分别留证。发布前按用户要求集中确认具体材料；外部权限不足提前准备补丁并如实交接，不伪造闭环。

2026-11-02：b1/b2 已有实际 RED→GREEN 与 CU 问题证据，其余为调研约束。

- Windows 大小写改名不能用 `.exists()` 证明最终名称正确；要枚举真实条目名，并验证内容与冲突行为。
- b1 原断言在 Windows 上误放过“API 成功但磁盘旧名未变”。规范化用于范围判断，不能把规范化返回的旧名称直接作为改名目标；直接保留请求 basename 已经通过 NTFS 验证，无需引入暂名与回滚复杂度。
- b1 实际 CU 还发现 DOM 测试中存在且文本正确的错误提示，在真实窗口可能因定位上下文缺失而不可见。只测 `.text()` 不代表视觉通过；这次定位修复通过前端回归/构建，真实可见性在用户停止 CU 后仍保留待复测。
- 后端 Docker tag 操作是添加别名，UI 的“重命名”需要先定义旧标签如何处理。
- 流式构建可复用已有能力，但不能因此丢掉重建锁、运行目标和旧镜像保护；缓存开关必须穿透到实际 argv。
- 扩展模块是已有安装能力的组合；共享/预装成员的归属与失败终态是执行前的数据设计，不宜靠卸载时临时猜。
- 计划、建议、实施、自动化、CU、用户验收、发布关闭分别记账；历史通过或免测不得继承为本版本 PASS。

实施后追加：出现的问题、根因证据、修复办法和防复发措施，关联实际提交/测试；不记录未经验证的猜测为事实。

- b2：为主菜单加入内部滚动时，嵌在其中的绝对定位子菜单会被裁切；子菜单必须独立放到 body 并使用视口坐标。菜单先隐藏测量、落位后再显示；焦点也要等 Vue 应用可见状态后设置，不能因 jsdom 允许聚焦隐藏节点就省掉这一步。
- b2：异步操作需保留打开时的菜单实例，完成后只关闭它自己；外部滚动和菜单内滚动必须分开处理，否则短屏菜单无法滚动到末项。
- b2 CU：保证子菜单“在视口内”仍不足以保证操作正确。长菜单 clamp 后覆盖 hover 触发按钮，会把随后点击重定向到子项，造成真实误移；应限制到所选侧的可用宽度并换行。用实际鼠标展开、执行后账本核对与局部几何回归共同验证，保留首次失败证据。
