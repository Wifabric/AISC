# b5 推荐模块定义与编辑

状态：本批及后续整合修正已合入 main，开发者证据见下方历史记录与 [PROGRESS](PROGRESS.md)；用户已报告统一验收通过。正式发布和反馈闭环见 [发布准备](release-readiness.md)。

以下保留本批实施时的基线、验证和决策过程，不将当时的未测项目改写为 PASS。

## 实施契约

- 用户配置目录独立 `extension-modules.json`，schema_version=1、revision、definitions、hidden_builtin_ids；跨进程锁、原子替换、revision 冲突拒绝覆盖，损坏/未知版本保留原文件并禁止保存。无旧版本数据时空初始化；从原子写备份恢复只在主文件缺失时执行。
- 成员包含 kind / identity / name / source_url，以 kind+identity 去重；不存凭据或安装状态。定义 ID 用 UUID。市场推荐中的“基础模块”入口可离线创建/编辑/复制/删除，通过现有三类搜索及单项推荐选择成员。
- 内置定义只读，修改通过复制为用户模块；隐藏内置定义不删受控清单，支持恢复。受控首发清单在 U-4 批准前为空，不擅自确定具体默认成员。
- 本批保存/删除只处理定义，不调用安装/卸载。目标应用记录与真实执行在 b6 单独实现；界面明确保存不会安装。

## 方案

保留现有六类单项推荐；新增基础模块入口，支持用户创建/复制、编辑成员、保存、删除定义。默认模块来自受控清单，用户修改用覆盖/副本表达，后续 catalog 更新不能静默抹掉修改。删除内置模块的展示/恢复语义在实现前写入规格。

成员必须带稳定市场身份与 kind，不用显示名做安装键。引用已有 Skill/MCP/Plugin 搜索选择能力，允许从同一模块添加不同种类成员；重复成员去重，失效来源给状态而非自动猜替代项。

定义与运行目标应用记录分开，保存定义不安装、删除定义不卸载（U-3 推荐）。离线可读写本地定义；未知 schema/损坏文件报错并保留原数据。实际存储路径在 U-3 确定后按既有 settings/data-root 约定落档。

## 首发成员清单门

U-4 当前只建议科研/开发两类，没有捏造未核验的具体安装条目。实施前逐项给出名称、kind、来源 URL/ID、引擎支持、认证要求及精简入选理由，用户确认后写入本批附表并实现。现有 catalog 每类十项不是默认全部安装。
