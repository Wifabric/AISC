# 经验记录

- 新一轮 preview 反馈使用独立活动计划；原归档中的免补测裁定不冒充本轮用户验收。
- 市场错误须沿真实常驻 CLI 协议复现，不能只用 mock 出来的成功响应证明修复。
- 本次根因在宿主旧 CLI pin（0.1.9.dev0 不认识 updates-check），不是容器镜像。
  恢复前必须取到同一目标准确的 argparse 拒绝证据；不能把任何空输出都解释为旧版本。
- 全局常驻 serve 池在真实进程测试结束时必须 drain；否则断言完成后 Tokio orphan
  reaper 仍等待子进程，测试不退出。显式清理后真实恢复测试 9.29 秒通过。
- 静态生产候选使用 `npm run tauri -- build --no-bundle`；普通 cargo release 未启用
  custom-protocol，会访问未启动的开发服务器，不能当作生产 UI 交付。
- Windows CU 在本机多截图/子对话框下，UIA 索引点击和焦点字段可能滞后；必须按最新
  主截图或子对话框截图选择坐标，并核对实际文本/状态，不能以“点击工具成功”当功能成功。
