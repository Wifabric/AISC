# Preview 修复规格

## b1 市场更新检查

复现用户在扩展/技能市场检查更新的空 envelope。修复真实根因，保留 CLI 的 JSON
协议与实际失败诊断；不得将空输出伪装为成功空列表，不得只隐藏 toast。检查失败可重试，
失败后常驻 CLI 与其它控制面命令仍可用。三类市场/已安装读取不回退。

## b2 功能简介与展开布局

已安装 Skills/MCP/Plugins 点击条目展示具体功能；技能组展开同时展示组简介和子技能，
子技能也有自身介绍。介绍描述能力、任务与适用场景，不能用“来自某仓库/某服务；
安装前核对说明与权限”作为正文替代。优先使用可靠上游描述/技能内容及可追溯中文说明，
缺失时明确缺失，不能虚构功能。保留独立来源信息。
已安装及市场详情在窄侧栏/弹窗内完整排版，长文本、按钮和焦点框不被父容器裁切，
详情框使用既有主题层级；键盘可展开收起，蓝框不覆盖正文或超出卡片。

## b3 默认 GitHub MCP

默认安装官方 GitHub MCP，遵循既有扩展配置结构和默认双引擎流程。
核对官方维护渠道与运行要求后确定 transport/版本，优先避免额外嵌套 Docker。
已有用户开关与自定义同名配置不被覆盖；不内置 token，不把缺少认证写成可调用成功。
首次安装、重复安装、已有配置升级和双引擎列表验证必须覆盖。

## b4 显式更新与体积

下载完成保持 Workbench 运行；用户点击退出更新才以正常双击 setup.exe 的方式启动
交互式安装器，不带静默参数，用户手动完成安装。
仅在安装成功后删除本次应用下载且验证过的安装包；取消/失败保留以供重试。
清理限制在应用自更新临时目录，不删除用户任意下载或手动选择的 exe。
比较 v2.1.16 与 preview.1 的资产大小及 bundle 项目，量化接近 350 MB 增长的来源，
删除冗余或改变分发方式前保持离线安装、checksum、升级/卸载和运行时依赖完整性。
以实际压缩安装包及展开体积报告优化量，不能仅报告源目录大小。

## b5 工作记录会话

右键分支会话从所选原生会话上下文创建独立分支，不修改原会话；Codex/Claude
均覆盖。启动出错时保留用户可读错误通知并直接回收此次失败的新标签，释放资源，
不关闭其它标签、不删除原记录。成功会话不误关闭。
单会话右键移除“新建会话”；工作记录/未归档分组“重命名”左侧放加号，按既有引擎
打开新标签。工作记录中新建会话直接归该记录，不短暂落入未归档或刷新后丢归属。

## b6 文件管理

文件/目录 Ctrl+C 将真实文件放入剪贴板；当剪贴板有文件时 Ctrl+V/右键粘贴到所选
目录，文件/空白区域的目标规则需明确。兼容 Windows Explorer 复制的文件；跨
工作区/远程路径按目标文件面实现，不将远端路径误认成本地文件。
Delete/右键删除可删文件/目录，遵循既有确认和错误反馈，不越过工作区边界。
Ctrl 切换选择，Shift 连续范围选择；目录拖动与文件同样生成 Bash/CLI 路径。
多选一起拖入时输入所有选中路径，使用既有终端转义规则覆盖空格、中文与 shell 字符，
不执行文本、不重复、选择/刷新/删除后的状态一致。
