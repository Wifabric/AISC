## 本轮发现并修正的文档问题

1. 原稿说“进入批次”，但缺少批次条目的可填写结构。现在提供关联任务、范围、已有实现、责任人、依赖、验收、状态和下一步模板。
2. 原稿同时要求 PR 单一账本和多处回写，可能让执行者重复维护状态。现在区分需求、批次、PR 三个层次，摘要引用同一份审查证据。
3. 阶段尚未启动时，候选没有明确存放位置。现在先使用既有 intake／backlog，确认范围后迁入阶段记录。
4. PR 关闭或只实现部分需求时，TODO 如何处理不够明确。现在要求保留缺口、替代方案或范围裁定，不自动完成或取消需求。

## 场景走查结果

方法：对每个输入场景，依据工作流写出下一步、责任人和状态出口；检查是否必须临时发明规则才能继续。这是同一编写者的静态自查，没有邀请独立评审者或执行远端操作。

| 场景 | 按文档得出的处理结果 | 规则位置 |
| --- | --- | --- |
| 有已批准 Issue，但没有 PR | 保留原自行开发批次；原验收规则继续适用 | §1、§3.1 |
| Issue 与 PR 对应同一个需求 | 关联一个 TODO，安排审查集成批次，不重复开发 | §3 |
| 新 PR 不在已批准范围内 | 先候选，列范围建议；已有决定直接引用 | §1–§3 |
| 阶段目录尚未创建 | 放既有 intake／backlog，保留来源，待范围确定后迁入 | §3 |
| 子 PR 目标为父 PR 分支 | 全仓收集，登记依赖；父项处理后重查子项差异 | §2、§5 |
| PR 只实现一半需求 | 同一需求保持未完成，明确缺口及其批次 | §3.1、§6 |
| 审查退回修正，作者提交新 head | 约定责任人修正，主审复查新提交及受影响验证 | §4、§6 |
| PR 关闭但需求仍成立 | 保留待实现任务或关联替代方案，不自动完成 TODO | §6 |
| PR 已合并但集成验证失败 | 保持已合入待验证，关联修正项；TODO 不打勾 | §5、§6 |
| 阶段收尾仍有未完成项 | 显式记录转期及裁定，沿用原收尾与发布要求 | §5；WIKI §1.1 |

这十种场景均能从文档中找到处理路径。走查证明的是规则可追溯；多人实际理解是否一致、能否减少遗漏和返工，需要后续试用验证。

## 阅读和演示顺序

1. 阅读 WIKI §1.5，确认三类输入、四个推进时机及职责。
2. 阅读工作流 §8，用虚构 DEMO-A 解释“已有实现如何替代自行开发批次”。
3. 查看 §3.1 和 §6 的模板，确认执行者能直接落笔。
4. 用“作者提交修正”和“PR 关闭未合并”两个场景，检查交接后是否知道下一步。

读者评审时优先记录：哪个术语不清楚、哪一步不知道由谁做、缺少什么输入、哪个状态无法继续。无需为展示文档效果实际合并 PR 或修改产品。

## 第二阶段：职责分工与双向交接

按用户“按照你给出的分工往前推进吧”的要求，将讨论稿分工整理为[开发职责](../workflows/development-roles.md)，补充[贡献者工作流](../workflows/contributor-workflow.md)，接入 WIKI §1.6。v0.1 讨论稿原样保留。

| 场景 | 贡献者侧输出／行动 | 主开发人员侧接续 | 自查结论 |
| --- | --- | --- | --- |
| 承接已排期任务 | 按贡献者 §2 补方案、确认承接 | PR intake §3.1 保持同一批次编号、验收与依赖 | 没有另起一套版本计划 |
| 新提议或已有实现 | 按贡献者 §1 分别走候选或成果交付 | PR intake §3 核对范围、去重及入批 | 不自动入版，不重复开发 |
| 自测缺环境 | 贡献者 §4、§7 说明 NOT RUN、影响与需要 | 主开发人员协调验证，原验收规则决定是否可继续 | 不把缺失验证变为通过 |
| 审查要求修正 | 贡献者 §6 给新提交、逐项说明和复验 | PR intake §4 对新 head 复审 | 修正不直接跳到合入 |
| 父 PR 合入或冲突 | 贡献者按协调结果更新分支与验证 | 主开发人员核对剩余 diff、依赖及集成顺序 | 双方对同一提交作出结论 |
| 开发人员无法继续 | 贡献者 §7 交分支、已做／未做与证据 | 主开发人员安排并记录实际接手 | 接手前不冒充已交接或已完成 |
| 合入后失败 | 贡献者承担约定修正和复验 | PR intake §5 保持未完成、协调跨任务影响 | 合并不代替验收 |
| 自查通过、等待用户验收 | 提供产物和可复现步骤 | 组织有效阶段模式要求的验收 | 用户决定权保留 |

完整虚构任务见贡献者 §8，逐步覆盖任务交出、PR 接收、退回、复审、集成验收和任务收口。该表和示例经过同一编写者静态走查，未实际分派团队成员、操作远端 PR 或修改产品。正式版本集成与发布仍按既有授权及有效阶段规则执行。
