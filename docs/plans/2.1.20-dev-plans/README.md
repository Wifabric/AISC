## 开工核对及进展

### B6 工作记录

工作记录批次 B6 已接入集合与记录菜单、原生保存窗口和预览页。导出按保存开始时的记录长度分段读取，只有全部读取成功才替换目标文件。预览中的技能和工具详情默认折叠，文件沿用资源管理器的工作区打开方式。删除确认使用置顶模态窗口，取消会保留选中的记录或集合。

开发验证覆盖 47 项会话用例（含超过预览上限的连续中文及导出期间追加记录）、44 项前端用例、类型检查和 423 项 Rust 用例（2 项忽略）。真实桌面的保存选择、链接打开、窗口层级和远程工作区留待集成候选核对。

### B7 工作目录与集合新建会话

标签栏与工作记录集合共用新建菜单。工作目录可输入并从对应父目录选择，建议仅展示文件夹。Claude、Codex 会话沿用集合跟踪，Bash 打开指定目录。通过集合打开个人能力或主题后，新建首个引擎会话时传递该集合和目录。

67 项前端测试及类型检查通过，包含下级目录提示、文件排除、传给 CLI 的目录和集合标识。实际终端的 `pwd`、主题启动、会话归档和键盘操作由集成候选验证。

### B5 设置与网络用量布局

设置导航统一提供「网络与用量」入口。订阅与节点管理靠近各自的操作，用量统计共享范围、单位和刷新按钮。供应商和模型分表展示，宽窗口可并列，窄窗口中各表可横向滚动。在统一 Preview 核对短窗口、系统缩放和实际订阅状态。

### B2 代理节点刷新（2026-11-23）

已合入 develop 的批次为[供应商 #109](https://github.com/Wifabric/AISC/pull/109) 和[代理节点 #110](https://github.com/Wifabric/AISC/pull/110)。后者集成提交为 `55ed6a18`。

在当前运行容器查询节点失败时，CLI 检查节点管理组件、订阅挂载和控制套接字，把对应原因交给工作台。刷新失败时清除旧节点选项，空策略组显示独立提示。

无网络的一次性 2.1.19 镜像容器使用新 CLI 验证。未挂载订阅、已挂载但服务未启动两种状态均取得预期诊断。启动真实 Mihomo 后，列出测试策略组、从 DIRECT 切到 REJECT、再次读取当前选择均通过。使用的是合成订阅。旧镜像缺组件分支有自动化覆盖。订阅与诊断用例 52 项通过，网络与用量页面已有用例 7 项通过，前端类型检查通过。用户截图对应环境的具体原因仍未知。

### B3 市场技能验证

用户选择「只安装所选技能及必要依赖」。单独安装 office-hours 时从同一份 Git 检出准备该技能，按运行文件引用复制共享程序与文档，缺少 Bun 时安装固定版本。普通 GitHub 技能的归档下载失败后改走 Git。

一次性、无网络的 Linux 容器使用真实 cc-switch 和上游提交 `8143a918` 的 office-hours 文件。通过本地 Git 映射和 npm 缓存安装，两种引擎的入口都读取到共享前言和启动标志 `SKILL_START_PROTO: 1`，评审辅助程序能读取 Git 帮助。技能列表只新增 office-hours。真实在线市场、引擎对话及桌面升级留给 Preview。

### B4 终端框选验证

Claude 和 Codex 开启鼠标跟踪后，文本拖动走 xterm 的选区路径，普通点击继续传给终端程序。鼠标在窗格外松开也会结束拖动。无头 Chrome 加载项目依赖的真实 xterm，模拟两种引擎的鼠标模式和普通 Bash，每种模式滚动三次，每次选区事件的内容均匹配预期。五项交互与接入测试通过。系统剪贴板、持续输出的实际引擎及右键菜单由统一 Preview 复核。
