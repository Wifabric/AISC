# Workbench 2.1.20-preview.1 验收清单

对应随包 CLI 0.3.1.dev0。请先看第 1 项，再安装候选。建议用一个可丢弃的工作区完成全表，已有测试账号和订阅可直接复用。涉及删除的步骤只选新建的测试记录。可逐项记录通过、失败或未测，并注明 Workbench 版本和使用的引擎。

| 项目 | 操作 | 通过条件 |
| --- | --- | --- |
| 1. 升级保留供应商 | 在 2.1.19 的测试工作区保存并选用一个有名称的第三方供应商，记下引擎、名称和端点。安装候选、打开原工作区，用候选自带资源构建镜像并重新启动该工作区。 | 原引擎下仍能找到、编辑并选用旧配置。账号可用时发起一条测试对话。反馈可附版本和名称，凭据留在本机。 |
| 2. 官方直连卡片 | 分别打开 Claude 和 Codex 供应商列表，并对照自建配置。 | 每种引擎的官方直连只显示一次，自建供应商沿用自己的名称，有编辑入口。 |
| 3. 刷新和切换节点 | 在测试工作区应用可用订阅，按提示重启容器。打开节点列表、切换至另一节点，再刷新一次。 | 列表显示策略组、节点及切换后的选中项。订阅或节点控制未生效时能看到对应原因和处理提示。 |
| 4. 市场技能 | 记下当前技能，市场搜索并只选择 office-hours 安装。重新打开已启用该技能的引擎，实际启动一次技能。 | 列表新增所选技能，已有技能保留。流程能继续读取共享文档并调用辅助程序。首次准备 Git 源或 Bun 需要可用网络。 |
| 5. 终端选中即复制 | 启用选中即复制，在 Claude、Codex 产生多屏输出，交互后向上滚动，连续三次框选不同文本，分别粘贴到记事本。再试右键复制及普通 Bash。 | 每次粘贴的内容与当次选区一致；正常点击、滚动和原有右键操作可用。 |
| 6. 设置与网络用量 | 从设置进入网络与用量，查看订阅、节点、供应商用量及模型用量。缩窄、缩短窗口后滚动，再依次刷新节点和用量。 | 分区可辨，窄窗口能到达操作按钮，按钮刷新其对应数据。 |
| 7. 结构化预览 | 打开含技能、工具参数、网址、有效文件路径和缺失路径的 Claude 或 Codex 记录。展开详情并打开有效目标。 | 详情默认折叠，展开后可读；有效路径和网址可打开，缺失工作区路径保留可读文本。 |
| 8. 导出 Markdown | 对长记录右键导出，再从预览右下角导出一次。分别保存至默认工作区及其他目录，核对首尾中文。第三次选择已有文件后取消保存。 | 两个入口均调起保存窗口；导出文件包含预览截断位置以后的末尾。取消后原文件内容不变。 |
| 9. 删除确认 | 在测试工作区新建临时集合和记录，使用独有的测试标题。分别对记录和集合右键删除，先按 Esc 取消，再对可丢弃对象确认。 | 删除记录时显示数量，说明是否涉及相关子会话与同名历史记录。删除集合时提示将终止运行中的成员会话并删除成员记录。取消后数据保留，确认后实际影响与提示一致。 |
| 10. 标签栏工作目录 | 在测试工作区准备一个带空格的目录、一个子目录及一个同前缀文件。通过标签栏新建菜单输入该前缀，选择目录并启动 Bash，在终端运行 `pwd`。 | 候选只显示匹配的目录，支持继续输入下一级。终端显示所选工作目录。 |
| 11. 集合中新建会话 | 从集合的加号选择目录，分别启动 Claude 或 Codex、Bash，再从个人能力或主题启动首个引擎会话。产生一条对话后回到工作记录。 | 可选择与标签栏相同的入口；引擎记录归入发起集合，目录正确。Bash 可在指定目录运行。 |

## 安装和反馈

安装前，在安装包所在目录运行 `Get-FileHash .\AISC-Workbench-2.1.20-preview.1-setup.exe -Algorithm SHA256`，核对结果与随包提供的 `.exe.sha256` 一致。安装后在设置中核对 Workbench 版本。容器内技能与迁移的验收需要以本版配套资源构建镜像，并让测试工作区使用新镜像。

若某项失败，记录序号、引擎、本地或 SSH 工作区、实际现象、能否重复即可。截图中可遮挡账号、密钥与订阅地址。真实账号、系统剪贴板、原生保存对话框和桌面缩放列入本轮用户实测。上版暂缓的偶发卡死继续单列。
