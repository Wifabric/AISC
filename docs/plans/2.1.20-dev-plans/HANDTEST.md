# Workbench 2.1.20-preview.3 验收清单

对应随包 CLI 0.3.1.dev0。请先看第 1 项，再安装候选。建议用一个可丢弃的工作区完成全表，已有测试账号和订阅可直接复用。涉及删除的步骤只选新建的测试记录。可逐项记录通过、失败或未测，并注明 Workbench 版本和使用的引擎。

| 项目 | 操作 | 通过条件 |
| --- | --- | --- |
| 1. 升级保留供应商 | 按下方「第 1 项专项」在旧版准备已有配置，用候选安装包覆盖升级，再打开原工作区核对。 | 升级前后逐条对得上，原选用状态保留，旧配置可编辑和切换。 |
| 2. 官方直连卡片 | 分别打开 Claude 和 Codex 供应商列表，并对照自建配置。 | 每种引擎的官方直连只显示一次，自建供应商沿用自己的名称，有编辑入口。 |
| 3. 刷新和切换节点 | 在测试工作区应用可用订阅，按提示重启容器。打开节点列表、切换至另一节点，再刷新一次。 | 列表显示策略组、节点及切换后的选中项。订阅或节点控制未生效时能看到对应原因和处理提示。 |
| 4. 市场技能 | 记下当前技能，市场搜索并只选择 office-hours 安装。重新打开已启用该技能的引擎，实际启动一次技能。 | 列表新增所选技能，已有技能保留。流程能继续读取共享文档并调用辅助程序。本候选的 x64 配套镜像已预置首次安装所需的上游文件和 Bun，可在断网环境验证。显式更新仍从上游取新版。 |
| 5. 终端选中即复制 | 启用选中即复制，在 Claude、Codex 产生多屏输出，交互后向上滚动，连续三次框选不同文本，分别粘贴到记事本。再试右键复制及普通 Bash。 | 每次粘贴的内容与当次选区一致；正常点击、滚动和原有右键操作可用。 |
| 6. 设置与网络用量 | 从设置进入网络与用量，查看订阅、节点、供应商用量及模型用量。缩窄、缩短窗口后滚动，再依次刷新节点和用量。 | 分区可辨，窄窗口能到达操作按钮，按钮刷新其对应数据。 |
| 7. 结构化预览 | 打开含技能、工具参数、网址、有效文件路径和缺失路径的 Claude 或 Codex 记录。展开详情并打开有效目标。 | 详情默认折叠，展开后可读；有效路径和网址可打开，缺失工作区路径保留可读文本。 |
| 8. 导出 Markdown | 对长记录右键导出，再从预览右下角导出一次。分别保存至默认工作区及其他目录，核对首尾中文。第三次选择已有文件后取消保存。 | 两个入口均调起保存窗口；导出文件包含预览截断位置以后的末尾。取消后原文件内容不变。 |
| 9. 删除确认 | 在测试工作区新建临时集合和记录，使用独有的测试标题。分别对记录和集合右键删除，先按 Esc 取消，再对可丢弃对象确认。 | 删除记录时显示数量，说明是否涉及相关子会话与同名历史记录。删除集合时提示将终止运行中的成员会话并删除成员记录。取消后数据保留，确认后实际影响与提示一致。 |
| 10. 标签栏工作目录 | 在测试工作区准备一个带空格的目录、一个子目录及一个同前缀文件。通过标签栏新建菜单输入该前缀，选择目录并启动 Bash，在终端运行 `pwd`。 | 候选只显示匹配的目录，支持继续输入下一级。终端显示所选工作目录。 |
| 11. 集合中新建会话 | 从集合的加号选择目录，分别启动 Claude 或 Codex、Bash，再从个人能力或主题启动首个引擎会话。产生一条对话后回到工作记录。 | 可选择与标签栏相同的入口；引擎记录归入发起集合，目录正确。Bash 可在指定目录运行。 |

## 第 1 项专项：旧版升级后 Provider 是否保留

**本次发布路径为正式 2.1.19 → 2.1.20-preview.3。** 在独立 Windows 测试环境操作，两版使用同一 Windows 用户、同一个工作区绝对路径和同一 AISC 数据目录。只有 Preview 的环境可测日常操作，升级专项需要从旧版开始。

1. **在旧版留样。** 先确认界面显示 2.1.19，工作区运行旧版配套镜像。在 Claude、Codex 下各保存一条有独特名称和端点的自建 Provider，例如 `QA-Claude-旧版` 和 `QA-Codex-旧版`。至少启用一条，另留一条已保存但未启用的配置作对照。有已填凭据或改过配置的旧预置时一并记录，这能覆盖旧预置迁移。使用专用测试凭据。
2. **留一份升级前证据。** 对每条记录抄下引擎、名称、端点、模型和是否当前选用。刷新旧版列表确认仍在，截取两侧引擎的卡片。退出旧版并留一份可还原的测试环境快照。凭据、订阅地址和原始数据库只留测试环境。
3. **执行覆盖升级。** 用统一验收的 Preview 安装包覆盖 2.1.19，保留应用数据。打开后核对版本号，选择原工作区。先检查安装后的列表（旧镜像可用时），再用 Preview 配套资源构建新镜像、让原工作区使用新镜像并检查第二次。记录首次缺失的阶段。检查结束前不要重新添加、导入或重新填写旧配置。
4. **先对账，再操作。** 对照升级前快照核对每条配置的字段和原选用状态。然后打开编辑页检查，再切换到另一条并切回。若测试账号可用，发一条最小请求，调用结果单列。截图只保留脱敏信息。
5. **判定。** 所有留样记录、关键字段和原选用状态保留，且能操作，方可记通过。任一旧配置消失、被重置或必须重建，记失败。出现缺失时保留现场，在同一工作区核对只读 CLI 列表及原 Provider ID，区分界面漏显和底层记录丢失。缺少旧版基线或没走覆盖安装，记未测。

若取得原反馈的版本号和升级前样本，用同一旧版快照分别还原「原升级路径」和「升级到本候选」两次。分别记录能否复现原故障和候选能否保留原配置。

## 安装和反馈

安装前，在安装包所在目录运行 `Get-FileHash .\AISC-Workbench-2.1.20-preview.3-setup.exe -Algorithm SHA256`，核对结果与随包提供的 `.exe.sha256` 一致。安装后在设置中核对 Workbench 版本。容器内技能与迁移的验收需要以本版配套资源构建镜像，并让测试工作区使用新镜像。

若某项失败，记录序号、引擎、本地或 SSH 工作区、实际现象、能否重复即可。截图中可遮挡账号、密钥与订阅地址。真实账号、系统剪贴板、原生保存对话框和桌面缩放列入本轮用户实测。上版暂缓的偶发卡死继续单列。

### Preview.3 技能市场搜索

启动测试工作区时，在「启动摘要 → 更改设置 → 镜像」填写 `aisc-handtest:2.1.20-preview.3`。从扩展市场进入「技能」，搜索 `matt`，查看首批 20 条和本次返回数。连续点「加载更多」，检查已有结果保留、后续技能可以点开；本组安装按钮的数量应与本组已显示的技能数一致。显示完这批结果后按钮消失。换个关键词重新搜索，应从首批开始。搜索数按上游当次返回计算。

### Preview.2 重点复测

- 第 3 项先在直连工作区刷新，核对界面给出的代理模式启动步骤。随后用已挂载订阅的代理工作区刷新，在手动策略组切换节点并再次刷新。自动策略组显示当前节点，可查看候选和测延迟。
- 第 4 项从市场单选 office-hours，安装期间打开其他面板，完成后在引擎中调用。断网检查首次安装，显式联网更新另行记录。
- 第 7 项展开 exec，核对命令、工作目录和输出首行。第 9 项同时打开测试 A、B 和无关对照会话，拖入 A、B 后立即核对标题，再删除集合，确认两个成员停止且对照仍能回复。
- 第 11 项先打开并关闭一个普通标签，再从集合自己的加号选择带空格的子目录，分别测试直接启动和通过主题启动。
- 在有长输出的终端快速滚动，再在多个标签间快速切换，分别做三轮。操作后检查终端输入和标签切换；记录卡住的持续时间和影响范围。
