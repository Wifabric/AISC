# b1 扩展市场整组安装修复 — 证据

- **branch**：`2.2.0-b1-ext-market-install`
- **基线**：`2.2.0-wangyuncepu-integration`（`f84cbcfc`）
- **结论**：整组与单技能安装共用同一「源选择 → 预检 → 安装」路径；单个仓库源失败不再把同组健康仓库标成 `blocked`；失败项保留真实传输诊断；扩展市场弹窗内展示进度并可取消；取消释放 busy 并记录 `unknown`（避免盲重试）。

## 根因与修复

#44 现象：`installed 0/53; mattpocock/skills:setup-matt-pocock-skills: skill group source preflight failed`，以及展开子技能后侧边栏「安装中」卡死、不可取消。

1. `_skill_group_operation` 用 `_github_git_env`（裸 `git ls-remote`）做整组硬预检，任一源探测失败即整组提前返回；健康仓库的子项落入兜底分支被标成 `blocked: skill group source preflight failed`，于是 0/N 且错误不可行动。
   - 修复：预检改用单技能安装同一套 `_github_skill_env`（archive 探测选直连/镜像），并逐仓库归因：失败仓库只标记自己的子项，健康仓库照常安装；不再出现泛化 `blocked` 文案。
2. 进度/结果只在侧边栏（`ExtensionsView`）渲染，市场弹窗内看不到，表现为卡死。
   - 修复：`ExtensionMarketDialog` 顶部新增进度条与「取消」按钮；结果错误继续在该弹窗的 `market-search-error` 展示。
3. 无取消入口。
   - 修复：store 新增 `beginCancelScope/cancellable/cancelActiveOperation/canCancelOperation`，`runOperation` 与 `runSkillGroupOperation` 都对在途请求做 race；取消后释放 busy、操作日志记 `unknown`（不提供盲重试），并提示已取消。

## review 修复

针对 code review 的 5 项发现：

1. **进度按项推进**（Spec）：适配器整组安装每完成一项即写 `<token>.json`（pid/total/completed/current/status）；store 以 1s 轮询 `skill-describe --id __aisc_group_operation__`（READ_OP，不走跨进程锁）增量更新 `activeOperation.completed`，UI 逐项刷新，而非结束时 0→N 跳变。
2. **取消真正生效**（Spec）：取消不再是纯客户端 `Promise.race`。`skill-describe --id __aisc_group_cancel__` 写入 `.cancel` 标记，并按 `/proc/*/stat` 的 PPid 扫描 SIGKILL 适配器派生的子进程；运行中的适配器在 `_run_cli` 前后检查标记并抛 `_GroupOperationCancelled`，剩余项标记 `cancelled`。store 的 `cancelActiveOperation` 走该通道，同时保留前端 race 以释放 busy。
3. **进度 UI 迁移去重**（Spec + Standards #1）：抽出共享组件 `ExtensionOperationProgress.vue`；进度只在 `ExtensionMarketDialog` 渲染，`ExtensionsView` 删除重复的 op-progress 渲染与样式（迁移而非复制）。
4. **staged_errors 类型化**（Standards #6）：`staged_errors: dict[str, tuple[str, str]]` 改为 `dict[str, StageError]`；`StageError(NamedTuple)` 携带 `StageErrorStatus` 枚举（`source_failed`/`missing`/`blocked`），不再散落字符串字面量。
5. **命名统一**（Standards #9）：`cancelableByKind` → `cancellableByKind`，与 `cancellable()`/`canCancelOperation` 拼写一致。
