## 结论

工作记录预览现在区分三类内容，并拆开 `/compact` 与其回复：

1. **用户输入 → 提问**：Claude 斜杠命令行（`<command-name>` + `<command-args>`）不再被当作注入上下文整段丢弃；规范化为 `kind="command"`，文本为「命令名 + 用户提供的对话」，在前端归入「提问」（`.cv-question`）。
2. **Skill 执行内容 → 思考与执行**：注入技能体（`Base directory for this skill:` / `<skill>`）仍为 `kind="skill"`，前端归入折叠的「思考与执行」（`.cv-activity`），不再与提问混淆。
3. **`/compact` 与回复拆开**：`/compact` 指令为 `kind="command"`（提问），其后的压缩摘要规范化为 `kind="compact"`（answer），二者分属提问/回复两段，不再并作一条用户消息。Codex 的 `compacted` 事件同样归一为 `kind="compact"`。

## 真实 seam（与工单 test 路径的偏差）

工单建议测试落在 `workbench/src/stores/__tests__/workRecords.test.ts`，但该文件只测工作记录集合状态，**不含预览解析**（与 b7 结论一致）。b8 的真实解析链为：

- 后端规范化：`src/aisc/application/conversation.py`
  - `_read_entries_claude`（斜杠命令 / `isCompactSummary`）
  - `_read_entries_codex`（`compacted` 事件）
- 前端分组：`workbench/src/features/history/conversationReading.ts` 的 `readingTurns`（`command` → questions，`compact` → answers，`skill` → activity）
- 渲染：`ConversationViewer.vue` → `RecordContent.vue`（沿用现有提问/执行/回复三段，无需新增区块）

因此回归测试落在真实行为 seam：前端解析 `conversationReading.test.ts` + 查看器 `conversationViewer.test.ts`，后端规范化 `tests/test_conversation.py`。

## local-gates / 环境说明

1. **2 个预存失败**（与 b8 无关，`PROJECT_MAP.md` §5 已登记的容器基线）：
   ```
   FAILED tests/test_extensions_adapter.py::MarketTests::test_office_hours_includes_only_selected_skill_and_referenced_runtime
   FAILED tests/test_extensions_adapter.py::MarketTests::test_skill_repo_remove_rejects_malformed_source
   ```
2. **共享 venv 指向主仓**：本 worktree 的 `.venv` 是主仓符号链接，其 editable `.pth` 指向主仓 `src/`。若直接跑 `bash scripts/local-gates.sh`，Python 步骤会加载主仓旧解析器，导致 b8 两条新用例假失败（4 failed）。以 `PYTHONPATH=<worktree>/src` 覆盖后仅剩上述 2 条预存失败。CI/全新 checkout 无此问题。
3. worktree 缺少 gitignored sidecar 占位，按 `PROJECT_MAP.md` 创建了
   `workbench/src-tauri/binaries/aisc-x86_64-unknown-linux-gnu` 与
   `workbench/src-tauri/nsis/bundle/aisc-bundle/`（均被 `.gitignore` 忽略，不入提交），cargo 方可构建。
