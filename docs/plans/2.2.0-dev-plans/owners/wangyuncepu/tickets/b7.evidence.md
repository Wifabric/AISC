## 结论

工作记录预览中的超链接在目标失效/不可验证时不再报错：

1. 点击失效链接：移除超链接（还原为普通文本），**不再**显示「无法打开链接：文件可能已移动，或不在当前工作区内」。
2. 预览渲染阶段：后端明确报告目录不存在/无效（`WB_ERR_WORKSPACE_INVALID` / `WB_ERR_WORKSPACE_NOT_FOUND`）时，链接目标直接判为 missing，超链接在渲染时即被移除；瞬时错误仍保留链接以便重试。

## 定位说明（与工单 test seam 的偏差）

工单/任务描述称解析逻辑位于 `workbench/src/stores/workRecords.ts`，但实际源码中该文件只负责工作记录集合状态，**不包含预览解析**。工作记录预览经 `WorkRecordsView.previewConversation` → `explorer.openConversationViewer` → `ConversationViewer.vue` → `RecordContent.vue` 渲染，链接解析/校验真实位置为：

- `workbench/src/features/history/RecordContent.vue`（点击与渲染时移除链接）
- `workbench/src/stores/workspaceExplorer.ts`（`missingRecordPaths` 目标有效性判定）
- （纯解析函数 `recordLink` 位于 `workbench/src/features/history/conversationReading.ts`，本次无需改动）

因此回归测试落在对应行为 seam：组件测试 `conversationViewer.test.ts` + store 测试 `workspaceExplorer.test.ts`；`workRecords.test.ts` 本身仍全绿（6/6），但该文件无链接解析 API 可测。
