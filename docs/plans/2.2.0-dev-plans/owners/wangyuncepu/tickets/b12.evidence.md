# b12 路径点击 — 证据

- **branch**：`2.2.0-b12-path-click`（基于 `2.2.0-wangyuncepu-integration`，含 b10/b11）
- **范围（D-9 子目标 3/3）**：在 b10 渲染管线之上加「输出中的路径可点击」。
  只消费 `parseTerminalMarkdown` 的 `text` / `list` 块文本，不重新解析引擎输出，
  不改 b10 的解析规则；`code` 块保持原样。默认（不开启链接）输出与 b10/b11
  逐字节一致。
- **验证日期**：2026-11-28

## 结论

在 `workbench/src/features/terminal/markdownRender.ts` 上做纯增量：

- 新增 `TerminalPathTarget`：`{ path, line?, column?, text, start, end }`。
  路径识别只覆盖 posix 形式（至少一层目录 + 带扩展名的文件名），可带
  `:line` / `:line:col` 后缀；裸文件名与 `https://…` 不匹配。
- 新增 `findTerminalPathTargets(text)`：在一个 `text` 行或列表项文本内识别
  全部路径目标，返回文件内行/列与文本内偏移。
- 新增 `locateTerminalPath(text, column)`：b12 的「点击定位」钩子——给定被点
  的 0 基列号，返回命中的目标（含 `line`/`column`）或 `null`。
- `TerminalRenderOptions` 增加 `pathLinks?: boolean`（默认 `false`）。开启后：
  - `text` 行与列表项文本中的路径被包裹为 OSC 8 文件链接
    （绝对路径 → `file://<path>`，相对路径 → `file:<path>` 交由 UI 按 workspace
    解析）；可见文本（含 `:line:col`）不变；
  - `code` 块（含折叠摘要）完全不变；
  - 列表的缩进/项目符号/有序标记与 b10 一致，散文原样保留。
- 不新增插件注册/扩展点，不引入 LaTeX；`parseTerminalMarkdown` 未改动。

与 b10 一样，实时 PTY 字节通路（`workspaceRuntime.paneStreams` →
`Terminal.writeChunks` → `term.write`）仍是原字节穿透，本工单交付的是纯渲染
seam 上的路径识别 / 点击定位 / 可点击标记；未接线到 live 通路，避免回归 TUI。

## 接线方案（文本流 vs TUI 字节流的适配点）

**适配点**：`Terminal.vue` 的 `paneStreams` 是同一份 PTY 字节缓冲——
既喂给 xterm 走原样透传，也作为 Markdown 视图的文本来源。

- **TUI / ANSI 字节流**：完全不变。`workspaceRuntime.paneStreams →
  Terminal.writeChunks → term.write` 仍是原字节穿透，未插入任何解析，
  ANSI/TUI 序列一根不少。
- **文本流（Markdown 视图）**：pane 右下角新增 `MD` 开关（`data-testid=
  markdown-toggle`）。开启后一个覆盖层读取 `paneStreams` 的尾部最多 512 KiB，
  依次经 `decodeStreamChunks`（base64→UTF-8）→ `stripTerminalAnsi`（去
  CSI/OSC/控制符）→ `buildMarkdownLines`；后者内部调用
  **`renderTerminalMarkdown`**（b10），并应用 b11 的 `folded` 与 b12 的
  `pathLinks: true`。覆盖层不写 xterm、不重启会话；关闭即回到原终端。
- **三种用户可见效果**：
  1. 代码块/列表基础渲染：fenced block 变 `── lang ──` 块 + 列表 `•`/序号；
  2. 折叠：点击代码块标题行 → `toggleCodeFold` 收起/展开，标题带 `▸/▾`；
  3. 路径点击：`pathLinks` 产生的 OSC 8 `file:` 目标被 `MarkdownOutputView`
     渲染为 `<a>`，点击经**浏览器的路径解析**（`locateTerminalPath` 在
     `buildMarkdownLines` 内把可见文本解析回 `TerminalPathTarget`）后由
     `useWorkspaceExplorerStore().openFile` 打开（遵循 F-A01 分层：组件不直接
     调 `workspaceOpen`）。
