## 结论

对应 D-4 / U-1：

1. **左侧工具栏只保留「刷新」**：文件/资源管理器头部工具栏不再有「新建文件 / 新建文件夹」（新建仍保留在右键菜单），仅剩「刷新」与「折叠资源管理器」。
2. **刷新绑定当前标签内容**：`onToolbarRefresh` 按 `explorer.activeKind` 分派——文件管理器刷新文件树/产物索引；工作记录刷新集合 + 会话列表；历史标签重扫会话。工作记录面板内的旧「⟳ 刷新」按钮已删除，侧边栏只有这一处刷新入口。
3. **新会话实时 push**：工作记录面板挂载时订阅会话活动事件通道；runtime 在 provider（claude/codex）PTY 有输出时推送事件，面板收到后自动 `refreshWorkRecords()`，无需手动点刷新。

## 实时 push 通道选型

- 通道：**前端 Pinia store 事件通道（Pub/Sub）**，非新增 Tauri 文件监听器。
  - 发布：`workbench/src/stores/workspaceRuntime.ts` 的 PTY `output` 分支调用 `announceWorkRecordsActivity()`，按 pane 节流 **5s**，仅 provider（claude/codex）pane，再调用 `workRecords.notifySessionActivity(workspace)`。
  - 订阅：`workbench/src/features/workspace-explorer/WorkRecordsView.vue` 挂载时 `records.onSessionActivity(...)`，仅当事件 workspace 等于当前面板 workspace 时刷新；卸载时退订。
  - 存储：`workbench/src/stores/workRecords.ts` 提供 `onSessionActivity` / `notifySessionActivity`（`Set` 监听器，异常隔离）。
- 为什么用 PTY 输出作为信号：provider 的会话 JSONL 写在数据根（workspace 之外），现有 `workspace://changed` 监听器覆盖不到；且 `conversation list` 会过滤「零用户消息」的会话，因此「会话真正出现」的时点应由 provider 实际写入/输出驱动。PTY 输出是 runtime 已有的实时事件源，按 pane 5s 节流避免长流式输出频繁触发会话扫描。事件通道由 U-1 明确允许（Tauri event 或 store subscription）。

## review 修复（2026-11-28）

> 本节覆盖上文「实时 push 通道选型」中的 PTY 输出方案：原实现以终端输出节流触发刷新，偏离 U-1「新会话事件驱动」的要求，已改正。

### 1. b5 push seam 改对（Spec，最重要）

- **新会话事件点**：`workbench/src/stores/workspaceRuntime.ts` 的 `openPane()`。该函数是 runtime/session 生命周期中**唯一**分配新 `sessionId` 并 `await ipc.openSession(...)` 的地方——新建标签、拆分新 pane、以及「工作记录内新建会话」都汇聚于此。
- **触发时机**：`ipc.openSession` 成功返回且 pane 仍然有效之后，若 `(agent === "claude" || agent === "codex") && (!resumeConversationId || forkSession)`，调用 `useWorkRecordsStore().notifySessionActivity(startingWorkspace)`。
  - 全新会话（`resumeConversationId == null`）与新 fork（`forkSession === true`）会写入新会话记录 → 通知刷新。
  - 普通 resume 复用已有会话 → 不触发，避免无意义全量扫描。
  - `bash` pane 不触发。
- **删除**：`workspaceRuntime.ts` 中 PTY `output` 分支的 `announceWorkRecordsActivity(tab, paneId)` 调用，以及 `WORK_RECORD_PUSH_THROTTLE_MS` / `workRecordPushAt` / `announceWorkRecordsActivity()` 定义。终端流式输出不再反复触发会话全量扫描。
- **订阅链路不变**：`WorkRecordsView.vue` 仍通过 `records.onSessionActivity(...)` 订阅；只是发布源从「每 5s 的 PTY 输出」改为「新会话创建」。事件通道 `onSessionActivity` / `notifySessionActivity` 保持原样。
- **回归测试**：`workbench/src/stores/__tests__/runtimeTabs.test.ts` 新增用例——新建 claude 会话触发 `onSessionActivity("/ws")`，带 `resumeConversationId` 的普通 resume 不触发。

### 2. Standards #5 Divergent Change

`workspaceRuntime.ts` 移除 b5 的 PTY 推送职责后，b5 只保留 `openPane` 成功后一次性的 `notifySessionActivity` 调用（会话生命周期天然归本文件）；文件内的 b 系列逻辑回到 b9 的探针 bookkeeping，单一职责恢复。

### 3. Standards #4 重复 prune 循环

`workspaceRuntime.ts` 新增 `prunePaneBookkeeping(livePaneIds, records, maps)` 统一 helper：
- `probeStuckTabs()` 的 4 个闭包 prune 循环（`probePhaseFor` / `lastProbeQueueDepth` / `paneLastActivityAt` / `paneLastFlushAt`）合并为 1 次调用。
- `resetStuckProbeState()` 的 3 个清空循环 + `probePhaseFor.clear()` 合并为 1 次调用（`livePaneIds === null` 表示全清）。

### 4. Standards #7 错误码重复枚举

`workspaceExplorer.ts` 新增共享映射 `WORKSPACE_ERRORS`（code → i18n key + `gone` 标记）与两个派生函数：
- `workspaceErrorI18n(error)`：把 `ConversationsPane.vue` / `WorkspaceExplorer.vue` 各自 switch 的错误码映射收敛到一处。
- `isWorkspaceGoneError(error)`：替换 `missingRecordPaths()` 中新增的 `/^WB_ERR_WORKSPACE_(?:INVALID|NOT_FOUND)$/` 正则。
两个组件改为直接调用 `workspaceErrorI18n`，错误码不再三处重复。

确认无引用后删除 `workRecords.refresh`、`explorer.toolbar.newFile`、`explorer.toolbar.newFolder`（zh-CN + en-US 各 3 个 key；`explorer.menu.newFile/newFolder` 仍被右键菜单使用，保留）。
