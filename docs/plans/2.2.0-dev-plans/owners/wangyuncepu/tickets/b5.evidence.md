## 结论

对应 D-4 / U-1：

1. **左侧工具栏只保留「刷新」**：文件/资源管理器头部工具栏不再有「新建文件 / 新建文件夹」（新建仍保留在右键菜单），仅剩「刷新」与「折叠资源管理器」。
2. **刷新绑定当前标签内容**：`onToolbarRefresh` 按 `explorer.activeKind` 分派——文件管理器刷新文件树/产物索引；工作记录刷新集合 + 会话列表；历史标签重扫会话。工作记录面板内的旧「⟳ 刷新」按钮已删除，侧边栏只有这一处刷新入口。
3. **新会话实时 push**：工作记录面板挂载时订阅会话活动事件通道；runtime 在 provider（claude/codex）PTY 有输出时推送事件，面板收到后自动 `refreshWorkRecords()`，无需手动点刷新。

## 实时 push 通道选型

- 通道：**前端 Pinia store 事件通道（Pub/Sub）**，非新增 Tauri 文件监听器。
  - 发布：`workbench/src/stores/workspaceRuntime.ts` 的 PTY `output` 分支调用 `announceWorkRecordsActivity()`，按 pane 节流 **5s**，仅 provider（claude/codex）pane，再调用 `workRecords.notifySessionActivity(workspace)`。
  - 订阅：`workbench/src/features/workspace-explorer/WorkRecordsView.vue` 挂载时 `records.onSessionActivity(...)`，仅当事件 workspace 等于当前面板 workspace 时刷新；卸载时退订。
  - 存储：`workbench/src/stores/workRecords.ts` 提供 `onSessionActivity` / `notifySessionActivity`（`Set` 监听器，异常隔离）。
- 为什么用 PTY 输出作为信号：provider 的会话 JSONL 写在数据根（workspace 之外），现有 `workspace://changed` 监听器覆盖不到；且 `conversation list` 会过滤「零用户消息」的会话，因此「会话真正出现」的时点应由 provider 实际写入/输出驱动。PTY 输出是 runtime 已有的实时事件源，按 pane 5s 节流避免长流式输出频繁触发会话扫描。事件通道由 U-1 明确允许（Tauri event 或 store subscription）。
