## 结论

新增纯函数渲染管线 `workbench/src/features/terminal/markdownRender.ts`：

- `parseTerminalMarkdown(input)`：把引擎文本切成 `text | code | list` 块模型。
  - fenced 代码块 ```` ```lang ... ``` ```` → `{ kind: "code", lang, code }`（未闭合
    的 fence 视为直到文本末尾的代码，兼容流式截断）。
  - 列表行 `- / * / + / 1. / 1)` → `{ kind: "list", items }`，保留缩进、序号与
    有序/无序标记。
- `renderTerminalMarkdown(input)`：把块模型渲染为终端文本。
  - 代码块：dim 的 `── lang ──` 头 + 原文代码行（不篡改内容）+ dim `──────` 尾，
    代码块作为独立块保留，原始 ``` 标记不再显示。
  - 列表：无序统一为 `• `，有序保留原序号（如 `1. `），缩进原样。
  - 其余散文原样透传（本层不处理标题/强调等，符合「基础可读性」深度）。

## 渲染 seam（b11/b12 基于此）

- 管线入口：`parseTerminalMarkdown` / `renderTerminalMarkdown`（纯函数，无副作用）。
- 引擎输出当前到达终端的路径：`workspaceRuntime.paneStreams`（PTY base64 字节，
  b9 探针同源）→ `Terminal.writeChunks` → `term.write`，**仍是原字节穿透**。
  实时 TUI 的 ANSI/光标控制流不能安全地按 Markdown 解析，所以本工单刻意把
  渲染做成独立纯管线，不改动 live PTY 字节通路，避免回归 TUI/高吞吐表现。
- b11（命令折叠）：消费 `parseTerminalMarkdown` 的 `code` 块，在渲染时给代码/
  长命令块加折叠标记，不改解析器。
- b12（路径点击）：消费 `text`/列表项的文本片段做路径识别与可点击化（xterm
  link provider 或渲染期标记），同样在块模型之上增量。
- 不引入插件注册/扩展点；两个子工单直接扩展固定渲染器。
