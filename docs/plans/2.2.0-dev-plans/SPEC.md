# Workbench 2.2.0 阶段规格（SPEC）

阶段：2 计划 · 目标版本 Workbench 2.2.0 · 状态：已确认（主开发定稿）
来源：`/to-spec`（Matt 流程）· 输入 `INTAKE.md`（已裁定，10 项纳入）

## 目标

把 10 项已裁定反馈（7 条新反馈 + 3 条悬账）转变成 Workbench 2.2.0 的可验收交付：修掉 4 个阻断 bug，重组 4 处 UX，给终端加基础富文本渲染，给标签卡住加可观测性，并清掉 Windows 升级脚本竞态。

## Problem Statement

- 用户被三个阻断性 bug 卡住：扩展市场「整组安装」报错且进度条卡死不能取消（#44）、Provider 官方直连切换/刷新报错（#45）、工作记录预览点超链接报错（#49）。
- 四处默认行为或信息组织不符合预期：安装默认给 claude/codex 装技能（#46）、侧边栏文件/资源管理器按钮冗余且刷新错位（#47）、网络节点信息庞杂主线不突出（#48）、工作记录预览把 Skill 内容当作用户话发送（#50）。
- 终端输出缺少可读性（需求 #5 富文本渲染）。
- 标签偶发卡住但没有复现手段，只能盲修（#23）。
- Windows 升级验收脚本存在进程清理竞态（todo）。

## Solution

一版 Workbench 2.2.0 统一交付：修复阻断 bug、重组四处 UX、为 Claude/Codex 终端加基础富文本渲染（Markdown / 命令折叠 / 路径点击）、给标签卡住加状态探针/日志与复现路径、修复升级脚本清理竞态。CLI 线仅在 Provider 切换（#45）与升级脚本（todo）处跟进，不独立定版。

## Out of scope（非目标）

1. 不新增产品线或引擎类型（仅维护 Claude / Codex / Bash 三引擎）。
2. Provider 不做架构级重构——只在现有官方直连上修 #45，不动 Provider 数据模型。
3. 需求 #5 限「终端输出可读性」，不做公式 LaTeX 渲染、不引入插件式渲染扩展点。
4. 安装器继续不做代码签名。
5. #44「无代理也能安装」的离线源/镜像内置方案转期——本版只做到「配代理能装 + 无代理清晰报错/可重试/可取消」。

## 用户故事

1. 作为扩展市场用户，我要在点「安装本组已显示的 N 项」后看到进度并最终装完，以便批量装技能不被卡死。
2. 作为扩展市场用户，我要在无代理环境下得到清晰报错并能重试或取消，以便知道卡在哪、不被挂起的进度条困住。
3. 作为扩展市场用户，我要在扩展市场界面（而非侧边栏）看到安装状态，以便安装反馈和操作在同一处。
4. 作为 Codex 用户，我要在 Provider 官方直连切换/刷新时不报错，以便顺利重新配置并登录客户端。
5. 作为新装用户，我要镜像不再默认给我装 claude/codex 技能，以便我的扩展配置全部来自扩展市场、无残留。
6. 作为侧边栏用户，我要文件/资源管理器左侧只保留「刷新」，以便界面简洁、不误点新建按钮。
7. 作为侧边栏用户，我要点刷新时刷新当前标签的实际内容（文件列表/工作记录），以便刷新不落空。
8. 作为工作记录用户，我要新会话出现时工作记录自动刷新，以便不用每次手动点。
9. 作为网络用户，我要在「网络与用量」一眼看到当前节点（代理组/节点名/延迟），以便主线不被庞杂信息淹没。
10. 作为网络用户，我要代理组可选、组下节点可选且带延迟，以便切换节点更直观。
11. 作为工作记录用户，我要点预览里的超链接不报错，以便能安全打开或识别失效链接。
12. 作为工作记录用户，我要失效链接在预览中不再是超链接，以便不被误导去点一个坏链接。
13. 作为工作记录用户，我要斜杠调用技能时用户提供的内容显示为提问、Skill 内容进「思考与执行」，以便预览如实反映我发的内容。
14. 作为工作记录用户，我要 `/compact` 指令与其回复在预览中拆开，以便看清各自的边界。
15. 作为终端用户，我要 Claude/Codex 的 Markdown 输出按基础可读性渲染，以便读代码块和列表更省力。
16. 作为终端用户，我要长命令可折叠，以便不被冗长输出刷屏。
17. 作为终端用户，我要输出中的路径可点击，以便快速定位文件。
18. 作为遇到标签卡住的用户，我要系统留下状态探针/日志和复现路径，以便问题可被定位（本版不承诺修复）。
19. 作为升级用户，我要 Windows 升级验收脚本只在进程真正退出后才判定清理成功，以便避免竞态误判。

## 实施决策

- **安装链路（D-1）**：安装进度/结果展示从侧边栏迁到扩展市场界面；整组安装与单技能安装共用同一 preflight / 安装 / 取消路径；代理可用走代理安装，不可用 fail-fast 报错并支持重试/取消。
- **Provider（D-2）**：仅在现有官方直连上修切换/刷新报错，沿用 2.1.19「重新应用当前配置」语义；不动 Provider 数据模型。
- **镜像默认产物（D-3）**：镜像默认产物清空技能/MCP/插件，保留 gh/npm/codex/claude 工具；扩展配置全部经扩展市场。
- **侧边栏（D-4）**：左侧工具栏只保留「刷新」；刷新动作绑定当前标签内容；新会话自动刷新机制：实时 push（事件通道推送到工作记录）。
- **网络节点（D-5）**：节点信息按「当前节点 → 代理组 → 组内节点」层级重组；代理组与节点均可选，节点带延迟。
- **工作记录超链接（D-6）**：预览中失效链接移除超链接化（显示为普通文本或删除）。
- **工作记录预览解析（D-7）**：解析区分「用户输入」与「Skill 执行内容」；`/compact` 指令与回复拆开整理。
- **富文本渲染（D-9）**：终端输出渲染 Markdown / 代码折叠 / 路径点击三能力，深度限「基础可读性」。
- **可观测性（D-8）**：标签卡住时输出状态探针/日志，形成可复现路径。
- **升级脚本竞态（D-10）**：清理成功判定改为「进程已退出」而非仅状态查询。

## 测试决策（seams）

- **最高 seam：Workbench 前端行为**（`npx vitest run` + `vue-tsc`/`npm run build`），覆盖 D-1/D-4/D-5/D-6/D-7 及 D-9 前端渲染。
- **CLI seam**（`python3 -m pytest tests/`），覆盖 D-2 Provider 切换、D-10 脚本竞态（若落地 CLI）。
- **Rust/Tauri seam**（`cargo test --lib`），覆盖安装/刷新 IPC 契约变更。
- **容器 seam**（重建镜像 + 集成测试），覆盖 D-3 镜像默认产物、D-9 引擎适配。
- **人工 seam**（HANDTEST 草案）：UI 视觉/交互验收（D-1 无代理报错交互、D-4 刷新交互、D-5 节点层级、D-7 预览拆解），阶段 3 落为可执行。
- **测试原则**：只测外部行为（用户可见的结果与契约），不测实现细节；优先复用现有测试（`tests/`、`workbench/` vitest），为每项 D-N 补对应验收形态。

## 约束

- 主线 Windows x64；Workbench 与 CLI 独立定版（本版 Workbench 2.2.0，CLI 仅在 D-2/D-10 触及处跟进）。
- 兼容 Claude / Codex / Bash 三引擎，不新增引擎或产品线。
- 沿用 ADR-001（stdlib CLI 架构）与 ADR-002（三轨分发）立场；Provider 不做架构级重构。
