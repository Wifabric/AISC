# v2.1.17-target — 生态与可靠性

> 2026-10-26 用户指示完成 v2.1.16 final 收尾并进入下一阶段。按默认裁定采用 **方案 A：生态与可靠性**；后续反馈如改变优先级，以追加批更新本索引，不回改已裁决记录。

## 目标

把 v2.1.16 已具备的 Skills / MCP / Plugins、自更新与无代理链路从“可用”推进到“可诊断、可恢复、可长期维护”。

## 范围

1. **市场元数据与更新信号**
   - skills.sh、Smithery、Claude plugin market 检索结果增加本地缓存与刷新策略；
   - 已安装项与市场元数据对齐，展示可更新状态；
   - 搜索 / 详情 / 安装链路分别记录来源与版本，避免同名技能来源漂移。
2. **扩展操作恢复能力**
   - 安装、更新、卸载失败后的状态回滚与重试入口；
   - 批量操作支持失败项单独重试；
   - 操作日志保留可直接复制的诊断信息。
3. **网络与健康诊断**
   - 新增扩展 / 更新网络健康报告：直连、ghfast、gh-proxy、API、asset 分层探测；
   - Workbench 自更新与 CLI 配对版本统一进入健康报告；
   - 保留“不默认系统代理”的裁定，只展示可用性与建议。
4. **发布与升级可靠性**
   - Workbench、CLI、bundle、镜像版本配对检查；
   - 升级后首次工作区启动的健康检查；
   - preview 阶段暴露的高频链路固化为冒烟测试。
5. **回归自动化**
   - 出厂 14 技能、市场搜索、无代理安装 / 更新、自更新 URL fallback 建立稳定契约；
   - 补充安装器升级矩阵与清理 / 重建路径的自动化预检。

## 非目标

- 不默认启用系统代理。
- 不引入新的重型后端服务；缓存与诊断优先落在本地数据根。
- 不重构 cc-switch SSOT；继续通过官方 CLI / SQLite 快照边界交互。
- 不在本阶段重写终端或 Work Records。

## 验收基线

- 每批保持 TDD：先写失败测试，再实现；
- 每批至少通过 targeted Python / Vitest / Rust 与相关静态契约；
- 收尾前执行 `scripts/local-gates.ps1`、sidecar 重建、vendor verify 与真实容器冒烟；
- preview 发布前记录无代理市场搜索、安装、更新、卸载与自更新检查结果。
