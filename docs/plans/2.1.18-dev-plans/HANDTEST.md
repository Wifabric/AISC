$qaRoot = Join-Path $env:TEMP ('AISC-2.1.18-qa-' + [guid]::NewGuid().ToString('N').Substring(0, 8))

## H1 / b1：精确大小写与冲突

**本轮候选**：`codex/2.1.18-b1-case-rename` 工作树的 `workbench/src-tauri/target/debug/workbench.exe`，精确 SHA256 见 PRETEST。版本显示仍为 2.1.17；这是带 b1 修复的开发候选。独立 QA 目录已准备，名称 `AISC-b1-QA-64b486cf`；进入时选本机，下一步完成预检，再启动。无需在终端输入模型指令。

**本轮状态**：用户委托 agent 已完成文件/目录改名、刷新重入及磁盘不覆盖检查。冲突文案初测不可见，已补前端修复并构建；用户随后取消 CU，已停止操作，修后文案复测 NOT RUN。当前窗口未切换到前端修正版；后续恢复测试时须先切换对应候选再复测冲突提示，不能要求用户在旧窗口验收新修复。

**前置**：本批候选已打开 `$qaRoot`；目录含上述三个条目及子文件；无需模型会话。

**操作**：
1. 文件侧栏右键 `Area.txt` → 重命名 → 输入 `AREA.txt` → Enter；右键 `Folder` → 重命名为 `FOLDER`。
2. 刷新文件侧栏，关闭并重新进入该工作区；执行下面只读命令。
3. 尝试把 `AREA.txt` 改为 `Occupied.txt`，记录错误；重新读两份文件。
4. 准备足够多的测试条目使列表可滚动，在最后一个可见行重复同名冲突及非法名称输入。错误文案应自动进入可见区域，输入仍可编辑；按 Escape 后输入与错误消失，原文件不变。

```powershell
Get-ChildItem -LiteralPath $qaRoot | Select-Object Name
Get-Content -LiteralPath (Join-Path $qaRoot 'AREA.txt')
Get-Content -LiteralPath (Join-Path $qaRoot 'FOLDER\child.txt')
Get-Content -LiteralPath (Join-Path $qaRoot 'Occupied.txt')
```

**理想结果**：枚举精确包含 `AREA.txt`、`FOLDER`、`Occupied.txt`；不残留旧大小写或临时名。内容依次 `qa-file`、`qa-child`、`keep-me`。冲突改名被拒绝且两文件均保留，UI 与磁盘一致。

**异常**：仅 UI 改名、刷新恢复旧名、条目/内容丢失、冲突被覆盖、留下未说明的临时文件。Remote 若本批修改对应实现，应在独立远程工作区另记一组结果，不由 Local PASS 代替。

## H2 / b2：底部、右侧和子菜单

**前置**：本批候选有足够工作记录成员使侧栏可滚动；至少一个成员可展开现有子菜单。开发者准备无私人内容的记录，记录 Windows 缩放与窗口尺寸。

**操作**：
1. 滚到列表底部，右键最靠窗口底边的成员，展开菜单中有子项的动作。
2. 将窗口缩窄、缩短，使菜单下方/右方空间不足；再次右键并展开子菜单，滚动菜单查看末项。
3. 用 Escape 关闭，验证焦点；再次右键后调整窗口尺寸/滚动侧栏。用一个测试成员执行“重命名”，记录命中的条目。

**理想结果**：主菜单向上/向左避让，子菜单独立选择可见方向；所有动作可见或可在菜单内部滚动到达。Escape 关闭并归还原触发处焦点；变更视口后正确重定位或关闭。只改所选测试成员名称。

**异常**：菜单/子菜单末项被窗外裁切，点击错成员，Escape 后焦点丢失，缩放使菜单偏离点击区。DOM 模拟测试通过但实际窗口异常仍判 FAIL。

## H3 / b3：镜像命名

**前置**：U-1 已定；开发者提供受 AISC 管理的独立测试镜像，记录其 image ID、全部 tags、另一个冲突 tag；Docker 运行。不得选择用户日常镜像。

**操作**：
1. 设置 → 磁盘与缓存 → 指定测试镜像行 → 重命名；核对默认建议，取消一次，刷新。
2. 再打开，输入开发者给出的未占用合法 tag，确认；刷新镜像列表并对照 Docker inspect 证据。
3. 重试非法名称和指向另一 ID 的冲突 tag；再验证带 registry port 的合法引用。

**理想结果**：取消不改 tags；新 tag 对应原 image ID；旧 tag 按 U-1 处理、其他 tags 保留。非法/冲突输入显示原因且无资源被覆盖；带 port 的仓库名完整保留。

**异常**：仍固定追加 `-renamed`、端口被截掉、改错镜像、删除其他 tags、部分失败只显示成功。新 tag 成功旧 tag 删除失败时必须分别显示实际状态。

## H4 / b4：两入口重建

**前置**：U-2 已定；提供独立镜像及引用它的一个测试容器，记录旧 ID。构建依赖网络可用，候选带匹配 CLI/bundle；无正式工作容器参与。

**操作**：
1. 保持测试容器运行；设置 → 磁盘与缓存 → 镜像行“重建”，观察预检查。按已定策略从容器行停止测试容器，再回到重建重新检查。
2. 阅读确认中的机器/镜像/容器，确认默认“无缓存”，开始；观察实际阶段/日志。成功后刷新列表，记录新/旧 ID 及旧引用说明。
3. 再开同一镜像的重建，选择“使用缓存”；本次构建进行中点击取消，核对任务终态和原镜像仍可用。
4. 回到工作区启动摘要，从“重建”进入；核对同样的目标、缓存选择和进度行为。切到 Remote 目标检查 U-2 定义的支持/禁用态。

**理想结果**：运行容器存在时按规则提示/阻止，不悄悄删容器；两入口目标一致。首次请求 no_cache=true，第二次 false（开发者提供 argv/事件证据，不只看复选框）。真实阶段持续更新；取消不显示成功。旧 ID 被停止容器引用时按裁定保留/说明；Remote 不回退本机。

**异常**：选 A 构建 latest/B、本机/Remote 串台、缓存开关只改 UI、没有终态、失败或取消后旧镜像丢失、重复点击并发建同一目标。镜像不存在及构建失败另由开发者隔离数据面验证，结果不得省略。

## H5 / b5：模块定义 CRUD

**前置**：U-3/U-4 已定且首发成员表已写入 b5；候选有独立应用配置/工作区，初始安装清单由开发者记录。

**操作**：
1. 扩展 → 扩展市场 → 推荐，查看原单项推荐和新“基础模块”入口；打开一个已确认的默认模块。
2. 创建或另存一个名为“QA 模块”的用户模块，依次添加一项 Skill、一项 MCP、一项 Plugin；重复加入其中一项，再移除其中一项并保存。
3. 重启候选再打开该模块；更改标题后保存；删除该用户模块定义。离线时另建定义并保存，再恢复网络。

**理想结果**：默认成员与批准表一致。三种成员显示来源；重复项不增加计数；移除一项后成员数为 2，重启仍为 2。编辑/删除定义前后真实安装资产清单不变。单项推荐及搜索仍可使用，离线编辑结果保留。

**异常**：只存内存、重启丢失、默认更新覆盖用户修改、显示名相同误合并不同来源、删定义同时卸载资产。b5 未交付 b6 时不得用假的“应用成功”完成测试。

## H6 / b6：应用、共享保护与失败恢复

**前置**：独立测试容器；模块 A/B 共享一个成员，另有用户预装成员和一个可由开发者制造可恢复失败的成员。基线列出各项真实来源/安装状态；U-3 已定。

**操作**：
1. 模块 A → 应用，阅读将安装/保留清单后确认；查看 x/y 和逐项终态。
2. 修复开发者准备的失败原因，点失败项重试；确认已成功项不重复执行。应用模块 B。
3. 模块 A → 卸载，核对将保留的共享项与预装项及原因，再确认；刷新三个已安装视图。
4. 切换到另一工作区/运行目标，核对状态；返回原目标，删除模块 B 的定义，核对资产未被隐式删除。

**理想结果**：部分失败明确显示，重试只处理需重试项；三类成员按能力显示。MCP 安装未认证仍标待认证，不显示可调用已验证。卸载 A 后共享项/预装项按 U-3 保留，只有符合归属条件的独占项移除。别的目标不继承已安装状态，删 B 定义不删资产。

**异常**：错误吞掉后显示整组成功、未知归属被删除、跨目标误操作、用户配置被覆盖、取消后无逐项结果。进程中断、用户手动卸载及恢复路径由定向自动化/数据面另记证据。
