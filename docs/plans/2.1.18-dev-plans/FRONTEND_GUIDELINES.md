# 前端实现约束

- 遵循 Vue 组件 → Pinia store → `lib/ipc.ts` → Rust/CLI 的现有层次；新增组件不直接绕过 store 调用任意 IPC。
- 操作捕获 workspace、runtime instance、目标机器及请求代次；异步结果仅回写同一上下文。模块定义可跨工作区共享时，安装状态仍不能跨目标共享。
- 延用现有颜色、间距、按钮和对话框，先修改已有组件；无需引入新 UI 库。所有新增文案进入 zh-CN/en-US，技术错误保留可复制诊断，但不把内部字段塞进正常操作文案。
- 菜单使用同一视口 CSS 坐标系，以实际尺寸定位；注意 Teleport、缩放和 visual viewport。子菜单单独避让，短屏 max-height+滚动；键盘可达、Escape 关闭、焦点归还。
- 镜像行操作紧邻原删除/重命名；主界面只展示任务进度一次。复用 BuildProgress 的阶段/日志/取消模式，最终状态来自后端结果。
- 模块卡片与单项推荐清晰区分；成员显示种类、名称、来源和当前状态。保存定义、应用、卸载各自独立；危险动作先列影响范围。
- Markdown/链接渲染沿用现有净化和路径范围校验，文档不能通过链接执行任意脚本或跨越允许文件范围。
- 验证包含：窄屏、长名称/错误、多语言、滚动/缩放、键盘、异步切换、重复点击。模拟 DOM 布局测试须另有真实 Windows UI 验证支撑。

- S16：普通新会话和主题入口分开，回答偏好独立；新手优先名称/规则/启用，进阶历史与诊断折叠。主题状态按当前 session 展示，草稿仅填入不代发；停止记录不关闭会话或删除历史。
