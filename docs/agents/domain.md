# Domain Docs

工程类 Skill 在探索代码库时如何消费本仓库的领域文档。

## 探索前先读

- **`GLOSSARY.md`**（仓库根）：本仓库的领域术语。
- **`docs/adr/`**：读与你要改的区域相关的 ADR。

若上述文件不存在，静默跳过，不提示缺失、不主动建议创建——`/domain-modeling` 会在术语或决策真正确定时按需创建。

## 文件结构

单上下文仓库（本仓库）：

```
/
├── GLOSSARY.md
├── docs/adr/
└── src/
```

## 用术语表词汇

你的输出命名领域概念时（工单标题、重构提议、假设、测试名），用 `GLOSSARY.md` 定义的术语，不漂移到术语表明确规避的同义词。

若所需概念不在术语表里，是个信号：要么你在造项目不用的语言（重新考虑），要么确有缺口（记下来交给 `/domain-modeling`）。

## 标记 ADR 冲突

若你的输出与既有 ADR 矛盾，显式指出，不要静默覆盖：

> _与 ADR-0007 冲突，但值得重开，因为……_
